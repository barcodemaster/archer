## 데이터 레이어 흐름

```
Resources/Data/EquipmentData.csv
        │
        ▼ (Resources.Load → 헤더 기반 파싱)
EquipmentDatabase (static)
    ├── GetAll() → EquipmentTable[]
    ├── GetById(id) → EquipmentTable
    └── PickRandomDrop() → 가중치 기반 랜덤
        │
        ▼ 드롭 시
EquipmentManager.CreateRandomItem()
    → EquipmentData (고유 인스턴스, GUID uid)
        │
        ├── AddItem() → _inventory에 추가
        ├── Equip() → _equipped[slot]에 장착
        ├── LevelUp() → 골드 소비 + 레벨 증가
        │
        ▼ 변경 시
SaveManager.Save() → JSON 파일
```

## EquipmentTable - CSV 스키마

> `Assets/Scripts/Data/EquipmentTable.cs`

```csharp
public class EquipmentTable
{
    public int id;                    // 고유 ID
    public string name;              // 장비 이름
    public string description;       // 설명
    public string icon;              // 아이콘 이름
    public EEquipSlot slot;          // 장착 슬롯 (Weapon, Top, Bottom, ...)
    public EEquipGrade grade;        // 등급 (Common ~ Legendary)
    public EMainStatType mainStatType; // 메인 스탯 (Attack / MaxHP)
    public float baseMainStat;      // 기본 메인 스탯
    public float mainStatPerLevel;  // 레벨당 메인 스탯 증가
    public float baseSubMin;        // 서브 스탯 최소값
    public float baseSubMax;        // 서브 스탯 최대값
    public int goldCostBase;        // 기본 강화 비용
    public int goldCostPerLevel;    // 레벨당 강화 비용 증가
    public int dropWeight;          // 드롭 가중치
    public string prefab;           // 3D 모델 경로 (무기만)
}
```

## EquipmentData - 고유 인스턴스

> `Assets/Scripts/Data/EquipmentData.cs`

> **왜 GUID uid가 필요한가?** 같은 테이블의 장비(예: "일반 검" tableId=1)를 여러 개 보유할 수 있다. `tableId`만으로는 인벤토리에서 "어떤 일반 검"인지 구분할 수 없다. GUID로 **모든 장비 인스턴스를 고유하게 식별**하여, 같은 종류의 장비라도 서브 스탯과 레벨이 다른 별개의 아이템으로 관리할 수 있다.

> **왜 서브 스탯이 생성 시 고정인가?** 서브 스탯을 나중에 리롤(재추첨)할 수 있으면, 플레이어가 원하는 스탯이 나올 때까지 반복하여 밸런스가 무너진다. 생성 시 랜덤으로 결정하고 이후 변경 불가로 설계하면 **장비마다 고유한 가치가 생기고, 더 좋은 장비를 파밍하는 동기**가 유지된다.

```csharp
[System.Serializable]
public class EquipmentData
{
    public string uid;              // GUID (고유 식별자)
    public int tableId;             // EquipmentTable 참조 ID
    public int level = 1;           // 현재 레벨 (최대 50)
    public ESubStatType subStatType;  // 서브 스탯 종류 (랜덤)
    public float subStatValue;      // 서브 스탯 수치 (랜덤)
    public bool isEquipped;
    public EEquipSlot equippedSlot;

    // 현재 레벨의 메인 스탯 = base + (level-1) × perLevel
    public float GetMainStat(EquipmentTable table)
    {
        return table.baseMainStat + (level - 1) * table.mainStatPerLevel;
    }

    // 강화 비용 = goldCostBase + level × goldCostPerLevel
    public int GetLevelUpCost(EquipmentTable table)
    {
        return table.goldCostBase + level * table.goldCostPerLevel;
    }
}
```

## EquipmentDatabase - CSV 파서

> `Assets/Scripts/Data/EquipmentDatabase.cs`

```csharp
public static class EquipmentDatabase
{
    private static EquipmentTable[] _all;
    private static int _totalWeight;  // 드롭 가중치 합계

    // 가중치 기반 랜덤 장비 선택
    public static EquipmentTable PickRandomDrop()
    {
        Init();
        if (_all.Length == 0) return null;

        int roll = Random.Range(0, _totalWeight);  // ①
        int cumulative = 0;
        foreach (var t in _all)
        {
            cumulative += t.dropWeight;  // ②
            if (roll < cumulative)
                return t;
        }
        return _all[_all.Length - 1];
    }
    ...
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | 0부터 전체 가중치 합계 사이에서 랜덤 정수를 뽑는다. 이 값이 "룰렛 휠의 바늘" 역할을 한다 |
| ② | 각 장비의 가중치를 순서대로 누적 합산하며, 누적값이 `roll`을 처음으로 초과하는 장비가 선택된다. 가중치가 높은 장비일수록 더 넓은 구간을 차지하여 선택 확률이 높다 |

### 드롭 확률 계산 예시

| 장비 | dropWeight | 확률 (totalWeight=100 기준) |
|------|-----------|---------------------------|
| 일반 검 | 40 | 40% |
| 희귀 활 | 30 | 30% |
| 에픽 지팡이 | 20 | 20% |
| 전설 대검 | 10 | 10% |

## EquipmentManager - 인벤토리 매니저

> `Assets/Scripts/Manager/EquipmentManager.cs`

> **왜 Observer 패턴(event)으로 UI를 갱신하는가?** `Equip()` 메서드에서 직접 `UI_EquipmentPanel.Refresh()`를 호출하면, EquipmentManager가 UI를 직접 알아야 하므로 Manager↔UI 결합도가 높아진다. `OnEquipChanged` 이벤트를 발행하면 **어떤 UI든 독립적으로 구독/해제**할 수 있고, 매니저는 UI의 존재를 알 필요가 없다. 나중에 장비 변경 시 사운드 재생이나 저장 기능을 추가해도, 매니저 코드를 수정하지 않고 새 구독자만 추가하면 된다.

> **왜 Ring1↔Ring2 슬롯 호환을 허용하는가?** 같은 종류의 반지를 두 개 장착하고 싶은 것은 자연스러운 요구다. 슬롯을 엄격하게 고정하면 Ring1 반지는 Ring1 슬롯에만 장착할 수 있어, 같은 반지 2개를 낄 수 없다. `IsSlotCompatible`에서 Ring1/Ring2를 상호 호환으로 설정하면 **플레이어의 빌드 자유도**가 높아진다.

```csharp
public class EquipmentManager : Singleton<EquipmentManager>
{
    private List<EquipmentData> _inventory = new();
    private Dictionary<EEquipSlot, EquipmentData> _equipped = new();

    public event Action OnInventoryChanged;
    public event Action OnEquipChanged;

    // 랜덤 장비 인스턴스 생성
    public EquipmentData CreateRandomItem()
    {
        EquipmentTable table = EquipmentDatabase.PickRandomDrop();
        if (table == null) return null;

        // 서브 스탯 랜덤 결정
        ESubStatType[] subTypes = (ESubStatType[])System.Enum.GetValues(typeof(ESubStatType));
        ESubStatType subType = subTypes[Random.Range(0, subTypes.Length)];
        float subValue = Random.Range(table.baseSubMin, table.baseSubMax);

        return new EquipmentData
        {
            uid = System.Guid.NewGuid().ToString(),  // ①
            tableId = table.id,
            level = 1,
            subStatType = subType,
            subStatValue = Mathf.Round(subValue * 10f) / 10f,  // ② 소수점 1자리
        };
    }

    // 장착 (기존 장비 자동 해제)
    public bool Equip(EquipmentData item, EEquipSlot slot)
    {
        if (!IsSlotCompatible(item, slot)) return false;  // ③

        if (_equipped.ContainsKey(slot))
        {
            var old = _equipped[slot];
            old.isEquipped = false;
        }

        item.isEquipped = true;
        item.equippedSlot = slot;
        _equipped[slot] = item;

        OnEquipChanged?.Invoke();
        SaveManager.Save();
        return true;
    }

    // 레벨업 (골드 소비)
    public bool LevelUp(EquipmentData item)
    {
        if (item.level >= 50) return false;

        EquipmentTable table = EquipmentDatabase.GetById(item.tableId);
        int cost = item.GetLevelUpCost(table);
        if (!GoldManager.Instance.SpendGold(cost)) return false;

        item.level++;
        OnInventoryChanged?.Invoke();
        if (item.isEquipped) OnEquipChanged?.Invoke();
        SaveManager.Save();
        return true;
    }

    // 슬롯 호환성 (Ring1↔Ring2, Pet1↔Pet2 허용)
    public bool IsSlotCompatible(EquipmentData item, EEquipSlot slot)
    {
        EquipmentTable table = EquipmentDatabase.GetById(item.tableId);
        if (table.slot == EEquipSlot.Ring1)
            return slot == EEquipSlot.Ring1 || slot == EEquipSlot.Ring2;  // ④
        if (table.slot == EEquipSlot.Pet1)
            return slot == EEquipSlot.Pet1 || slot == EEquipSlot.Pet2;
        return table.slot == slot;
    }

    // 전투 스탯 합산
    public float GetTotalAttackBonus() { ... }   // Attack 메인 스탯 합계
    public float GetTotalMaxHpBonus() { ... }    // MaxHP 메인 스탯 합계
    public float GetTotalSubStat(ESubStatType type) { ... }  // 특정 서브 스탯 합계
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | `Guid.NewGuid()`로 전역 고유 식별자를 생성한다. 같은 테이블의 장비라도 각 인스턴스가 고유 uid를 가져 인벤토리에서 구분된다 |
| ② | `Round(value × 10) / 10`으로 소수점 첫째 자리까지 반올림한다. UI 표시와 저장 시 불필요한 소수점 자릿수를 제거한다 |
| ③ | 장착 전 슬롯 호환성을 검사한다. 무기를 방어구 슬롯에 끼우는 등 잘못된 장착을 방지한다 |
| ④ | Ring1 타입 장비는 Ring1과 Ring2 슬롯 모두에 장착 가능하다. 같은 종류의 반지 2개를 동시에 끼는 듀얼 링 빌드를 허용한다 |

### 슬롯 호환성 다이어그램

```
EquipmentTable.slot    →    장착 가능 슬롯
─────────────────────────────────────────
Weapon                →    Weapon
Top                   →    Top
Bottom                →    Bottom
Bracelet              →    Bracelet
Ring1                 →    Ring1, Ring2   ← 듀얼 링
Pet1                  →    Pet1, Pet2     ← 듀얼 펫
```

## SaveManager - JSON 세이브/로드

> `Assets/Scripts/Manager/SaveManager.cs`

```csharp
[System.Serializable]
public class EquipmentSaveEntry
{
    public string uid;
    public int tableId;
    public int level;
    public ESubStatType subStatType;
    public float subStatValue;
    public bool isEquipped;
    public EEquipSlot equippedSlot;
}

[System.Serializable]
public class SaveData
{
    public int gold;
    public List<EquipmentSaveEntry> items = new();
}

public static class SaveManager
{
    private static string SavePath
        => System.IO.Path.Combine(Application.persistentDataPath, "save.json");

    public static void Save()
    {
        SaveData data = EquipmentManager.Instance.ToSaveData();
        string json = JsonUtility.ToJson(data, true);  // prettyPrint
        System.IO.File.WriteAllText(SavePath, json);
    }

    public static void Load()
    {
        if (!System.IO.File.Exists(SavePath)) return;

        string json = System.IO.File.ReadAllText(SavePath);
        SaveData data = JsonUtility.FromJson<SaveData>(json);
        if (data == null) return;

        GoldManager.Instance.SetGold(data.gold);
        EquipmentManager.Instance.LoadFromSave(data);
    }
}
```

## EquipmentVisual - 무기 본 어태치먼트

> `Assets/Scripts/Controllers/EquipmentVisual.cs`

> **왜 런타임에 동적으로 본 어태치하는가?** 무기별로 다른 3D 모델을 가진 캐릭터 프리팹을 미리 만들어두면, 무기가 추가될 때마다 프리팹 수가 늘어난다. 런타임에 `Resources.Load`로 무기 모델을 로드하고 본(bone)에 동적 부착하면, **하나의 캐릭터 프리팹으로 모든 무기를 시각화**할 수 있다. 장비 변경 이벤트를 구독하여 자동으로 모델을 교체한다.

```csharp
public class EquipmentVisual : MonoBehaviour
{
    private Transform _weaponBone;
    private GameObject _weaponInstance;

    private void Awake()
    {
        // 재귀적으로 "weapon_r" 본 탐색
        _weaponBone = FindBoneRecursive(transform, "weapon_r");
    }

    private void OnEnable()
    {
        // 장비 변경 이벤트 구독
        EquipmentManager.Instance.OnEquipChanged += RefreshWeapon;
        RefreshWeapon();
    }

    public void RefreshWeapon()
    {
        if (_weaponInstance != null) Destroy(_weaponInstance);
        if (_weaponBone == null) return;

        var equipped = EquipmentManager.Instance.Equipped;
        if (!equipped.TryGetValue(EEquipSlot.Weapon, out EquipmentData weaponData))
            return;

        EquipmentTable table = EquipmentDatabase.GetById(weaponData.tableId);
        if (table == null || string.IsNullOrEmpty(table.prefab)) return;

        // Resources에서 프리팹 로드 후 본에 어태치
        GameObject prefab = Resources.Load<GameObject>(table.prefab);
        _weaponInstance = Instantiate(prefab, _weaponBone);
    }
}
```

### 무기 시각화 흐름

```
EquipmentManager.Equip() → OnEquipChanged 이벤트
    │
    ▼
EquipmentVisual.RefreshWeapon()
    ├── 기존 무기 Destroy
    ├── EquipmentDatabase.GetById() → prefab 경로
    ├── Resources.Load<GameObject>(prefab)
    └── Instantiate(prefab, _weaponBone)
         └── localPosition/Scale 세팅
```
