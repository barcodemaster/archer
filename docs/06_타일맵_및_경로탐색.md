### 설계 의도

> **왜 전체 배열 대신 스파스(sparse) 저장인가?** 20×20 맵에서 대부분의 타일은 Path(통행로)이고, 벽이나 물은 일부에 불과하다. 400칸 전체를 배열로 저장하면 Path 타일 정보가 불필요하게 메모리를 차지한다. Override만 저장하면 **실제 특수 타일 수에 비례하는 메모리만 사용**하고, 직렬화 데이터도 작아져 에디터 성능이 향상된다.

- **스파스 저장**: 기본이 Path이므로 Path가 아닌 타일만 `_tileOverrides`에 저장 → 메모리 효율적
- **Dictionary 캐시**: `BuildCache()`로 리스트를 Dictionary로 변환하여 O(1) 조회 (에디터 fallback은 O(n))

```csharp
// 월드 → 그리드 (바닥을 1m 단위 그리드로 분할)
public Vector2Int WorldToGrid(Vector3 worldPos)
{
    int x = Mathf.FloorToInt(worldPos.x - _origin.x + 0.5f);
    int z = Mathf.FloorToInt(worldPos.z - _origin.z + 0.5f);
    return new Vector2Int(x, z);
}

// 그리드 → 월드 (타일 중심 좌표)
public Vector3 GridToWorld(int x, int z)
{
    return new Vector3(_origin.x + x, _origin.y, _origin.z + z);
}
```

### 통과 판정

```csharp
// 메인 API: 월드 좌표 기반 통과 판정
public bool CanPass(Vector3 worldPos, ETilePassFlag flags)
{
    if (_width == 0 || _height == 0) return true;

    Vector2Int grid = WorldToGrid(worldPos);
    // 맵 경계 밖은 무조건 이동 불가
    if (grid.x < 0 || grid.x >= _width || grid.y < 0 || grid.y >= _height)  // ①
        return false;

    // 타일 타입 통과 판정
    ETileType tileType = GetTile(grid.x, grid.y);
    if (!IsTilePassable(tileType, flags)) return false;

    // 블록 통과 판정 (WallPass 플래그 필요)
    if (GetBlockIndex(grid.x, grid.y) >= 0)
        return (flags & ETilePassFlag.WallPass) != 0;  // ③

    return true;
}

// 타일 타입 × 플래그 통과 매트릭스
public static bool IsTilePassable(ETileType tileType, ETilePassFlag flags)
{
    switch (tileType)
    {
        case ETileType.Path:  return (flags & (Walk | Fly)) != 0;  // ②
        case ETileType.Wall:  return (flags & WallPass) != 0;
        case ETileType.Water: return (flags & (Fly | WaterWalk)) != 0;
        case ETileType.Spike: return (flags & (Walk | Fly)) != 0;
        default: return false;
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | 그리드 범위를 벗어난 좌표는 무조건 이동 불가로 처리하여, 맵 밖으로 나가는 것을 방지한다 |
| ② | 비트 AND 연산 `(flags & Walk) != 0`으로 해당 플래그가 켜져 있는지 O(1)로 판정한다. OR 조합(`Walk | Fly`)으로 "둘 중 하나라도 있으면 통과" 조건을 표현한다 |
| ③ | 블록(장애물 오브젝트)이 배치된 타일은 `WallPass` 플래그가 있어야만 통과할 수 있다 |

### 통과 매트릭스

| 타일\플래그 | Walk | Fly | WaterWalk | WallPass |
|------------|------|-----|-----------|----------|
| Path | O | O | - | - |
| Wall | X | X | X | O |
| Water | X | O | O | - |
| Spike | O | O | - | - |
| Block | X | X | X | O |

### Greedy Rectangle Merge 알고리즘

> **왜 이 알고리즘이 필요한가?** 20×20 맵에서 벽 타일이 50개라면, 단순 구현으로는 BoxCollider 50개가 생성된다. Unity 물리 엔진은 콜라이더 수에 비례하여 연산량이 증가하므로, 이는 모바일에서 심각한 성능 저하를 유발한다. Greedy Rectangle Merge는 **인접한 같은 타입의 타일을 최대한 큰 직사각형으로 병합**하여, 50개의 콜라이더를 5~10개로 줄인다. 물리 연산 부하가 80% 이상 감소하는 효과가 있다.

```csharp
private void CreateMergedColliders<T>(
    List<Vector2Int> positions, Transform container, string namePrefix)
    where T : Component
{
    HashSet<Vector2Int> remaining = new HashSet<Vector2Int>(positions);

    while (remaining.Count > 0)
    {
        // 1. row-major 순서로 시작점 찾기
        Vector2Int start = default;
        int minVal = int.MaxValue;
        foreach (var p in remaining)
        {
            int val = p.y * _width + p.x;
            if (val < minVal) { minVal = val; start = p; }
        }

        // 2. 가로(x)로 확장
        int xEnd = start.x;
        while (remaining.Contains(new Vector2Int(xEnd + 1, start.y)))  // ①
            xEnd++;

        // 3. 세로(z)로 확장 (strip 전체가 존재해야)
        int zEnd = start.y;
        bool canExpand = true;
        while (canExpand)  // ②
        {
            int nextZ = zEnd + 1;
            for (int xi = start.x; xi <= xEnd; xi++)
            {
                if (!remaining.Contains(new Vector2Int(xi, nextZ)))
                { canExpand = false; break; }
            }
            if (canExpand) zEnd = nextZ;
        }

        // 4. 사각형 영역 제거
        for (int zi = start.y; zi <= zEnd; zi++)
            for (int xi = start.x; xi <= xEnd; xi++)
                remaining.Remove(new Vector2Int(xi, zi));  // ③

        // 5. 병합된 사각형에 단일 BoxCollider 생성
        int sizeX = xEnd - start.x + 1;
        int sizeZ = zEnd - start.y + 1;
        GameObject obj = new GameObject($"{namePrefix}_{start.x}_{start.y}");
        obj.transform.SetParent(container);
        BoxCollider bc = obj.AddComponent<BoxCollider>();
        bc.size = new Vector3(sizeX, 2f, sizeZ);  // ④
        obj.AddComponent<T>();
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | 시작점에서 오른쪽(+x)으로 연속된 타일이 있는 한 계속 확장한다. 가로 방향 최대 스트립을 먼저 결정한다 |
| ② | 가로 스트립이 확정되면, 아래쪽(+z)으로 같은 너비의 스트립이 통째로 존재하는지 확인하며 세로로 확장한다. 한 칸이라도 빠지면 확장을 멈춘다 |
| ③ | 확정된 직사각형 영역의 모든 타일을 `remaining`에서 제거하여, 다음 반복에서 중복 처리되지 않게 한다 |
| ④ | 병합된 영역 크기에 맞는 단일 BoxCollider를 생성한다. 높이 2f는 캐릭터가 벽 위로 넘지 못하게 하는 충분한 높이이다 |

### Greedy Merge 시각화

```
Before (9개 개별 콜라이더):        After (2개 병합 콜라이더):
┌─┬─┬─┐                           ┌─────┐
│W│W│W│                           │  W  │ ← 1개 BoxCollider (3×2)
├─┼─┼─┤                           │     │
│W│W│W│                           └─────┘
├─┼─┼─┤                           ┌─────┐
│ │W│W│                           │ W   │ ← 1개 BoxCollider (2×1)
└─┴─┴─┘                           └─────┘

성능 개선: 콜라이더 수 9 → 2 (77% 감소)
```

## AStarPathfinder - A* 경로 탐색

> `Assets/Scripts/Utils/AStarPathfinder.cs`

> **왜 `PriorityQueue` 대신 `SortedSet`인가?** C#의 `PriorityQueue<T>`는 .NET 6부터 추가되었는데, Unity의 C# 버전에서는 사용할 수 없는 경우가 있다. `SortedSet`은 모든 C# 버전에서 동작하며 O(log n) 삽입/삭제/최소 조회를 제공한다. 추가로, A*에서는 이미 발견한 노드의 비용이 갱신될 수 있는데, `PriorityQueue`는 기존 노드를 제거/갱신하는 것이 O(n)인 반면, `SortedSet`은 **O(log n)으로 노드 갱신이 가능**하여 실질적으로 더 효율적이다.

> **왜 Manhattan 휴리스틱인가?** 이 게임의 A*는 4방향(상하좌우) 이동만 허용한다. Euclidean(직선거리) 휴리스틱을 쓰면 대각선 거리를 과소평가(underestimate)하여 불필요한 노드를 더 많이 탐색하게 된다. Manhattan 거리는 **4방향 이동에서 정확한 최소 이동 횟수를 반환**하므로, admissible(과대평가하지 않음)하면서도 가장 효율적인 탐색을 보장한다.

```csharp
public static class AStarPathfinder
{
    private struct Node
    {
        public Vector2Int pos;
        public int gCost;       // 시작점에서의 거리
        public int hCost;       // 목표까지 추정 거리 (Manhattan)
        public int fCost => gCost + hCost;
        public Vector2Int parent;
    }

    // 4방향 탐색
    private static readonly Vector2Int[] Dirs = {
        new(0, 1), new(0, -1), new(1, 0), new(-1, 0)
    };

    public static List<Vector2Int> FindPath(
        TileMap tileMap, Vector2Int from, Vector2Int to, ETilePassFlag passFlags)
    {
        if (from == to) return new List<Vector2Int>();

        // 목표가 이동 불가면 인접 이동 가능 타일로 대체
        if (!IsWalkable(tileMap, to, passFlags))
        {
            Vector2Int? alt = FindNearestWalkable(tileMap, to, passFlags);
            if (alt == null) return new List<Vector2Int>();
            to = alt.Value;
        }

        // allNodes: 모든 발견 노드 (gCost가 더 낮으면 갱신)
        Dictionary<Vector2Int, Node> allNodes = new();

        // openSet: SortedSet으로 fCost → hCost → 좌표 순 정렬
        SortedSet<(int fCost, int hCost, int posX, int posY)> openSet = new();

        Node startNode = new Node
        {
            pos = from, gCost = 0,
            hCost = ManhattanDist(from, to), parent = from
        };
        allNodes[from] = startNode;
        openSet.Add((startNode.fCost, startNode.hCost, from.x, from.y));

        while (openSet.Count > 0)
        {
            var current = openSet.Min;  // ①
            openSet.Remove(current);
            Vector2Int curPos = new(current.posX, current.posY);

            if (curPos == to)
                return ReconstructPath(allNodes, from, to);

            Node curNode = allNodes[curPos];

            foreach (Vector2Int dir in Dirs)
            {
                Vector2Int next = curPos + dir;
                if (next.x < 0 || next.x >= w || next.y < 0 || next.y >= h)
                    continue;
                if (!IsWalkable(tileMap, next, passFlags))
                    continue;

                int newG = curNode.gCost + 1;  // ②

                if (allNodes.TryGetValue(next, out Node existing)
                    && existing.gCost <= newG)  // ③
                    continue;

                // 더 좋은 경로 발견 → 노드 갱신
                if (allNodes.ContainsKey(next))
                    openSet.Remove((existing.fCost, existing.hCost, next.x, next.y));  // ④

                Node nextNode = new Node
                {
                    pos = next, gCost = newG,
                    hCost = ManhattanDist(next, to), parent = curPos
                };
                allNodes[next] = nextNode;
                openSet.Add((nextNode.fCost, nextNode.hCost, next.x, next.y));
            }
        }

        return new List<Vector2Int>();  // 경로 없음
    }

    // 걸을 수 있는지: 타일 통과 + 블록 없음
    private static bool IsWalkable(TileMap tileMap, Vector2Int pos, ETilePassFlag flags)
    {
        ETileType tile = tileMap.GetTile(pos.x, pos.y);
        if (!TileMap.IsTilePassable(tile, flags)) return false;
        if (!tileMap.CanPassBlock(pos.x, pos.y)) return false;
        return true;
    }

    private static int ManhattanDist(Vector2Int a, Vector2Int b)
        => Mathf.Abs(a.x - b.x) + Mathf.Abs(a.y - b.y);

    private static List<Vector2Int> ReconstructPath(
        Dictionary<Vector2Int, Node> nodes, Vector2Int from, Vector2Int to)
    {
        List<Vector2Int> path = new();
        Vector2Int cur = to;
        while (cur != from)
        {
            path.Add(cur);
            cur = nodes[cur].parent;  // ⑤
        }
        path.Reverse();
        return path;  // from 제외, to 포함
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | SortedSet에서 `fCost`가 가장 작은 노드를 O(log n)으로 꺼낸다. fCost = gCost(실제 거리) + hCost(추정 거리)가 최소인 노드가 최적 경로 후보다 |
| ② | 4방향 이동이므로 인접 노드까지의 이동 비용은 항상 1이다. 현재 노드의 gCost에 1을 더해 이웃의 새 gCost를 계산한다 |
| ③ | 이미 발견된 노드의 기존 gCost가 새 경로보다 작거나 같으면, 더 좋은 경로가 이미 있으므로 스킵한다 |
| ④ | 더 좋은 경로를 발견했으므로, 기존 노드를 SortedSet에서 제거 후 갱신된 비용으로 재삽입한다. O(log n)으로 노드 갱신이 가능하다 |
| ⑤ | 도착점에서 시작점까지 `parent` 링크를 따라 역추적하여 경로를 복원한다. 결과를 Reverse하면 시작→도착 순서가 된다 |

### A* 최적화 포인트

| 최적화 | 구현 |
|--------|------|
| **SortedSet** | C#의 `SortedSet<(int,int,int,int)>`으로 O(log n) 삽입/삭제/최소 조회 |
| **Dirty Flag** | MonsterBase에서 플레이어 그리드 변경 시에만 `_pathDirty = true` |
| **Timer** | 0.5초 인터벌로 A* 실행 빈도 제한 |
| **이동 불가 목표 대체** | 목표가 벽이면 인접 이동 가능 타일로 자동 대체 |


## SpikeTile - 가시 함정

> `Assets/Scripts/Map/SpikeTile.cs`

> **왜 이동/정지를 다르게 처리하는가?** 이동 중인 플레이어는 가시 위를 빠르게 지나가므로, 한 번 강한 데미지(20)를 주고 긴 쿨다운(1.5초)을 적용한다. 반면 가시 위에 멈춰 서 있으면, 약한 데미지(5)를 짧은 간격(0.5초)으로 반복하여 **"여기 서 있으면 안 된다"는 지속적 압박**을 준다. 두 타이머를 분리한 이유는, 이동 중에는 `baseDamageTimer`가 빠른 재진입 데미지를 방지하고, 정지 시에는 `continuousDamageTimer`가 독립적으로 틱을 관리하기 위함이다.

```csharp
public class SpikeTile : MonoBehaviour
{
    [SerializeField] private float _baseDamage = 20f;        // 이동 중 데미지
    [SerializeField] private float _baseDamageInterval = 1.5f;
    [SerializeField] private float _continuousDamage = 5f;   // 정지 시 데미지
    [SerializeField] private float _continuousDamageInterval = 0.5f;

    private float _baseDamageTimer;       // 항상 흐름 (exit 후에도 지속)
    private float _continuousDamageTimer; // exit 시 리셋

    public void OnTriggerStay(Collider other)
    {
        PlayerController player = other.GetComponent<PlayerController>();
        if (player == null) return;

        if (player.State == EState.Move)
        {
            // 이동 중: 높은 데미지, 긴 인터벌
            if (_baseDamageTimer <= 0f)
            {
                player.TakeDamage(_baseDamage);
                _baseDamageTimer = _baseDamageInterval;
                _continuousDamageTimer = 0f;
            }
        }
        else
        {
            // 정지: 낮은 데미지, 짧은 인터벌 (지속 데미지)
            _continuousDamageTimer -= Time.deltaTime;
            if (_continuousDamageTimer <= 0f)
            {
                player.TakeDamage(_continuousDamage);
                _continuousDamageTimer = _continuousDamageInterval;
            }
        }
    }
}
```

### 가시 데미지 타이밍

```
이동 중 진입:  ──20dmg──────────────20dmg──────────
              └── 1.5초 인터벌 ──┘

정지 중:      ──5dmg──5dmg──5dmg──5dmg──
              └ 0.5초 └ 0.5초 └ 0.5초

퇴장 후 재진입: baseDamageTimer는 지속 (빠른 재진입 방지)
              continuousDamageTimer는 리셋
```
