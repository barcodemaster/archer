# 04. 몬스터 시스템

## 개요

`MonsterBase` 추상 클래스를 기반으로 Template Method 패턴을 적용하여 8개 이상의 몬스터 변종을 구현합니다.

---

## MonsterBase - 추상 베이스 클래스

> **왜 Template Method 패턴인가?** 8개 이상의 몬스터 변종이 "HP 초기화, 물리 설정, 경로 추종, 사망 처리" 등 공통 로직을 공유한다. 이 로직을 각 몬스터에 복붙하면 버그 수정 시 8곳을 모두 고쳐야 한다. Template Method는 **공통 로직은 부모 클래스에서 한 번만 작성**하고, 각 변종은 `OnDie()`, `Update()` 등을 오버라이드하여 고유 행동만 구현하면 된다. 새 몬스터를 추가할 때도 `MonsterBase`를 상속받으면 기본 기능이 모두 준비되어 있다.

> `Assets/Scripts/Controllers/MonsterBase.cs`

```csharp
public abstract class MonsterBase : MonoBehaviour
```

### Template Method 패턴

```
MonsterBase (abstract)
    │
    ├── Start()        ← 공통 초기화 (HP, 물리, HPBar, 타겟 탐색)
    │   └── virtual    ← 서브클래스에서 base.Start() 호출 후 추가 초기화
    │
    ├── Update()       ← 공통 루프 (경로 갱신, dirty 플래그)
    │   └── virtual    ← 서브클래스에서 base.Update() 호출 후 AI 로직
    │
    ├── OnDie()        ← 사망 시 호출 (기본 빈 구현)
    │   └── virtual    ← SplitterMonster에서 자식 스폰
    │
    ├── UpdateAnimation() ← 상태별 애니메이션 (기본 8 상태)
    │   └── virtual       ← 서브클래스에서 커스텀 가능
    │
    └── 공통 유틸리티:
        ├── CanMoveTo(pos)     ← 타일맵 통과 판정
        ├── MoveToward(dir, speed) ← Rigidbody/Transform 이동
        ├── GetPathDirection() ← A* 경로 다음 웨이포인트
        ├── RefreshPath()      ← A* 경로 갱신
        ├── Knockback(dir, force) ← 넉백
        └── StopMovement()     ← 정지
```

### 물리 시스템

> **왜 overlap/non-overlap으로 나눴는가?** 박쥐처럼 비행하는 몬스터가 플레이어와 물리적으로 부딪혀 밀리면 부자연스럽다. 반면 스켈레톤같은 지상 몬스터는 플레이어를 물리적으로 밀어야 위협감이 있다. `_overlapWithPlayer` 플래그로 이 두 가지를 분기하여, **비행 몬스터는 Trigger로 겹치면서 데미지만 주고, 지상 몬스터는 Rigidbody 충돌로 밀기까지 수행**한다.

```csharp
protected virtual void Start()
{
    // 비겹침 몬스터만 물리 콜라이더 + Rigidbody 추가
    if (!_overlapWithPlayer)
    {
        CapsuleCollider physCapsule = GetComponent<CapsuleCollider>();
        if (physCapsule == null || physCapsule.isTrigger)
            physCapsule = gameObject.AddComponent<CapsuleCollider>();
        physCapsule.isTrigger = false;
        physCapsule.radius = _physicsRadius;
        physCapsule.height = _physicsHeight;

        Rigidbody rb = GetComponent<Rigidbody>();
        if (rb == null)
            rb = gameObject.AddComponent<Rigidbody>();
        rb.useGravity = false;
        rb.constraints = RigidbodyConstraints.FreezePositionY
            | RigidbodyConstraints.FreezeRotation;
        rb.mass = _weight;

        if (_immovable)
            _rb.constraints = RigidbodyConstraints.FreezeAll;
    }
}
```

| 유형 | _overlapWithPlayer | 물리 | 데미지 전달 |
|------|-------------------|------|------------|
| 일반 근접 | false | Rigidbody + CapsuleCollider | OnCollisionStay → Push |
| 비행/겹침 | true | Trigger Collider만 | OnTriggerStay → TakeDamage |
| 고정형 | false + _immovable | FreezeAll | OnCollisionStay |

### 경로 추종 (A* Dirty Flag)

> **왜 매 프레임 A*를 돌리지 않는가?** A*는 맵 크기에 따라 수백 개의 노드를 탐색하는 비용이 큰 연산이다. 몬스터가 10마리 있으면 매 프레임 10번의 A*가 실행되어 프레임 드롭이 발생한다. Dirty Flag + 0.5초 타이머 조합은 **플레이어가 실제로 다른 그리드로 이동했을 때만, 최소 0.5초 간격으로 경로를 갱신**한다. 0.5초면 사람이 느끼기에 충분히 빠른 반응이면서, 불필요한 연산을 90% 이상 줄인다.

```csharp
protected virtual void Update()
{
    // 플레이어 그리드 변경 감지 → dirty 플래그만 설정
    if (_lastTargetGrid != GetTargetGrid())
    {
        _pathDirty = true;
        _lastTargetGrid = GetTargetGrid();
    }

    // 타이머 만료 + dirty일 때만 실제 갱신 (0.5초 인터벌)
    _pathRefreshTimer -= Time.deltaTime;
    if (_pathDirty && _pathRefreshTimer <= 0f)
    {
        RefreshPath();       // A* 탐색 실행
        _pathDirty = false;
        _pathRefreshTimer = PATH_REFRESH_INTERVAL;
    }
}
```

## 주요 몬스터 상세 분석

### BatMonster - 비행 돌진

> `Assets/Scripts/Controllers/BatMonster.cs`

```csharp
public class BatMonster : MonsterBase
{
    [SerializeField] private float _chaseSpeed = 2f;
    [SerializeField] private float _chargeSpeed = 12f;
    [SerializeField] private float _chargeDistance = 6f;

    protected override void Update()
    {
        base.Update();
        if (State == EState.Die || Target == null) return;

        if (State == EState.Attack)
        {
            // 돌진: 기록된 방향으로 직진
            float step = _chargeSpeed * Time.deltaTime;
            Vector3 chargeNext = transform.position + _chargeDirection * step;  // ①

            if (!CanMoveTo(chargeNext))
            {
                // 장애물에 막힘 → 돌진 중단, 추적 모드로 복귀
                _chargeTimer = Random.Range(_chargeIntervalMin, _chargeIntervalMax);
                State = EState.Move;
                return;
            }
            transform.position = chargeNext;
            _chargedDistance += step;  // ②

            if (_chargedDistance >= _chargeDistance)
            {
                // 돌진 완료 → 추적 복귀
                State = EState.Move;
            }
        }
        else
        {
            // 추적: A* 경로로 이동
            State = EState.Move;
            Vector3 dir = GetPathDirection();
            MoveToward(dir, _chaseSpeed);

            _chargeTimer -= Time.deltaTime;
            if (_chargeTimer <= 0f)
            {
                // 돌진 시작: 현재 플레이어 방향으로 직진
                _chargeDirection = (Target.position - transform.position).normalized;  // ③
                State = EState.Attack;
            }
        }
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | 돌진 중에는 A* 경로를 무시하고, 돌진 시작 시 기록해둔 `_chargeDirection`으로 직선 이동한다. 타일맵 통과 판정(`CanMoveTo`)으로 벽에 막히면 즉시 추적 모드로 복귀한다 |
| ② | 매 프레임 이동한 거리를 누적하여, 총 돌진 거리(`_chargeDistance`)에 도달하면 돌진을 종료한다 |
| ③ | 돌진 시작 시점의 플레이어 방향을 기록한다. 돌진 중에는 이 방향이 고정되므로, 플레이어가 피하면 빗나가는 패턴이 된다 |

**AI 흐름:**
```
Chase (A* 추적, _chaseSpeed)
    │  _chargeTimer 카운트다운
    ▼  timer <= 0
Charge (직선 돌진, _chargeSpeed × 6배)
    │  _chargedDistance 누적
    ├── 장애물 충돌 → Chase 복귀
    └── 거리 완료 → Chase 복귀
```

### ImpMischief - 보스 (3가지 스킬 셔플)

> `Assets/Scripts/Controllers/ImpMischief.cs`

```csharp
public class ImpMischief : MonsterBase
{
    private int[] _skillOrder = { 0, 1, 2 };
    private int _skillIndex;

    // Fisher-Yates 셔플
    private void ShuffleSkills()
    {
        for (int i = _skillOrder.Length - 1; i > 0; i--)
        {
            int j = Random.Range(0, i + 1);  // ①
            (_skillOrder[i], _skillOrder[j]) = (_skillOrder[j], _skillOrder[i]);  // ②
        }
        _skillIndex = 0;
    }

    private IEnumerator ExecuteNextSkill()
    {
        int skill = _skillOrder[_skillIndex];
        State = _skillAnimNumber[skill];  // Skill1/Skill2/Skill3

        switch (skill)
        {
            case 0: yield return SkillFireball(); break;   // 3방향 파이어볼
            case 1: yield return SkillHeadbutt(); break;   // 돌진 박치기
            case 2: yield return SkillRoll(); break;       // 구르기 돌진
        }

        _skillIndex++;
        if (_skillIndex >= _skillOrder.Length)
            ShuffleSkills();  // ③ 3개 모두 사용 후 리셔플
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | Fisher-Yates 셔플: 뒤에서부터 랜덤 인덱스 `j`(0~i 범위)를 뽑는다. 모든 순열이 동일한 확률로 나오는 균등 셔플을 보장한다 |
| ② | C# 튜플 스왑으로 `_skillOrder[i]`와 `_skillOrder[j]`의 값을 교환한다. 임시 변수 없이 한 줄로 스왑이 가능하다 |
| ③ | 3개 스킬을 모두 사용하면 다시 셔플하여 새로운 순서로 반복한다. 같은 스킬이 연속으로 나오지 않으면서도 예측 불가능한 패턴을 만든다 |

**보스 AI 흐름:**
```
Chase (A* 추적)
    │  _chaseTimer 만료
    ▼
Skill (셔플 순서)
    ├── Fireball: 3방향 파이어볼 발사 (spread ±20°)
    │   └── ProjectileBase(Straight) + FireExplosion
    │
    ├── Headbutt: 전방 돌진 + OverlapSphere 판정
    │   └── 전진 → 플레이어 히트 체크 → 후퇴 대기
    │
    └── Roll: 구르기 돌진 + CanMoveTo 체크
        └── 벽까지 직진 + 플레이어 히트 체크
    │
    ▼ 3개 모두 사용
ShuffleSkills() → Chase 복귀
```

### SplitterMonster - 분열

> `Assets/Scripts/Controllers/SplitterMonster.cs`

> **왜 `RegisterMonster`가 필요한가?** 분열 몬스터가 죽으면 자식 몬스터가 동적으로 생성된다. 하지만 StageManager는 스테이지 시작 시 등록된 몬스터만 `_aliveMonsters`에서 추적한다. `RegisterMonster`를 호출하지 않으면 자식 몬스터가 살아있어도 **스테이지 클리어 판정이 먼저 발동**되어, 남은 몬스터를 무시하고 출구가 열리는 버그가 생긴다.

```csharp
public class SplitterMonster : MonsterBase
{
    [SerializeField] private GameObject _childPrefab;
    [SerializeField] private int _childCount = 2;
    [SerializeField] private float _spawnOffset = 0.5f;

    // Template Method: OnDie() 오버라이드
    protected override void OnDie()
    {
        if (_childPrefab == null) return;

        Vector3 right = transform.right;
        for (int i = 0; i < _childCount; i++)
        {
            float offset = (i - (_childCount - 1) / 2f) * _spawnOffset;
            Vector3 spawnPos = transform.position + right * offset;
            GameObject child = Instantiate(_childPrefab, spawnPos, transform.rotation);
            MonsterBase childMonster = child.GetComponent<MonsterBase>();
            if (childMonster != null)
                StageManager.Instance.RegisterMonster(childMonster);
                // alive 목록에 동적 등록 → 스테이지 클리어 조건에 포함
        }
    }
}
```

### GhostMonster - 포물선 점프 유령

> `Assets/Scripts/Controllers/GhostMonster.cs`

> **왜 포물선 점프인가?** 일반적인 A* 추적만으로는 모든 근접 몬스터가 비슷한 움직임을 보인다. 포물선 점프는 **예측 불가능한 이동 패턴**을 만들어 플레이어가 회피 타이밍을 읽기 어렵게 한다. 또한 점프 중에는 Y축 위치가 변하므로 시각적으로 "유령이 떠다니는" 느낌을 강화한다.

```csharp
public class GhostMonster : MonsterBase
{
    [SerializeField] private float _jumpDistance = 3f;
    [SerializeField] private float _jumpHeight = 2f;
    [SerializeField] private float _jumpDuration = 0.5f;
    [SerializeField] private float _chaseRange = 8f;
    [SerializeField] private float _wanderRadius = 4f;
    [SerializeField] private float _wanderSpeed = 1f;

    private Vector3 _homePosition;

    private void UpdateJump()
    {
        _jumpProgress += Time.deltaTime / _jumpDuration;
        if (_jumpProgress >= 1f)
        {
            _isJumping = false;
            transform.position = new Vector3(_jumpEnd.x, 0f, _jumpEnd.z);
            State = EState.Idle;
            return;
        }

        Vector3 pos = Vector3.Lerp(_jumpStart, _jumpEnd, _jumpProgress);
        pos.y = Mathf.Sin(_jumpProgress * Mathf.PI) * _jumpHeight;  // ① 포물선
        transform.position = pos;
    }

    private void StartJump()
    {
        _jumpStart = transform.position;
        Vector3 jumpDir = GetJumpDirection();
        _jumpEnd = _jumpStart + new Vector3(jumpDir.x, 0f, jumpDir.z) * _jumpDistance;

        if (!CanMoveTo(_jumpEnd))                              // ②
        {
            bool found = false;
            for (int i = 0; i < 10; i++)                       // ③ 최대 10회 재시도
            {
                float angle = Random.Range(0f, 360f) * Mathf.Deg2Rad;
                jumpDir = new Vector3(Mathf.Cos(angle), 0f, Mathf.Sin(angle));
                Vector3 candidate = _jumpStart + jumpDir * _jumpDistance;
                if (CanMoveTo(candidate))
                {
                    _jumpEnd = candidate;
                    found = true;
                    break;
                }
            }
            if (!found) { _jumpTimer = 0.5f; return; }        // ④
        }

        transform.rotation = Quaternion.LookRotation(jumpDir);
        _jumpProgress = 0f;
        _isJumping = true;
    }

    private Vector3 GetJumpDirection()
    {
        // chaseRange 내 → 플레이어 방향
        if (Target != null &&
            Vector3.Distance(transform.position, Target.position) <= _chaseRange)
            return (Target.position - transform.position).normalized;  // ⑤

        // 범위 밖 → 홈 포인트 주변 랜덤
        float angle = Random.Range(0f, 360f) * Mathf.Deg2Rad;
        float dist = Random.Range(0f, _wanderRadius);
        Vector3 wanderTarget = _homePosition +
            new Vector3(Mathf.Cos(angle) * dist, 0f, Mathf.Sin(angle) * dist);
        return (wanderTarget - transform.position).normalized;
    }

    private void UpdateWander()
    {
        // 홈 포인트 주변을 _wanderSpeed로 천천히 배회
        if (!_hasWanderTarget ||
            Vector3.Distance(transform.position, _wanderTarget) < 0.3f)
            PickWanderTarget();                                 // ⑥

        Vector3 dir = (_wanderTarget - transform.position).normalized;
        Vector3 nextPos = transform.position + dir * _wanderSpeed * Time.deltaTime;
        if (CanMoveTo(nextPos))
            transform.position = nextPos;
        else
            PickWanderTarget();
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | `Sin(progress × π)`로 0→1→0 포물선 높이를 만든다. progress 0.5(중간점)에서 최대 높이에 도달하고, 시작/끝에서 0이 된다 |
| ② | 목표 착지점이 벽이나 물 등 이동 불가 타일이면 착지를 거부한다 |
| ③ | 랜덤 방향으로 최대 10회 재시도하여 유효한 착지점을 찾는다. 360도 전방위 탐색으로 코너에 갇히는 것을 방지한다 |
| ④ | 10회 모두 실패하면 점프를 취소하고 0.5초 후 재시도한다. 매우 좁은 공간에서 무한 루프를 방지하는 안전장치다 |
| ⑤ | 추적 범위(_chaseRange=8) 내에 플레이어가 있으면 플레이어 방향으로 점프한다. 범위 밖이면 홈 주변을 배회한다 |
| ⑥ | `PickWanderTarget()`은 홈 포인트에서 _wanderRadius 내 랜덤 위치를 선택한다. 도착하거나 벽에 막히면 새 목적지를 고른다 |

### TreantMinion - 4방향 점프 + 착지 발사

> `Assets/Scripts/Controllers/TreantMinion.cs`

> **왜 4방향(상하좌우)으로만 점프하는가?** 8방향이나 자유 방향 대신 4방향으로 제한하면, 플레이어가 **점프 패턴을 학습하고 피할 수 있는 여지**가 생긴다. 동시에 착지 시 4방향 발사와 조합되면, 점프 방향과 발사 방향이 겹쳐 특정 위치가 안전지대가 되는 퍼즐적 요소가 추가된다.

```csharp
public class TreantMinion : MonsterBase
{
    private static readonly Vector3[] CARDINAL_DIRS =
    {
        Vector3.forward, Vector3.back,
        Vector3.right, Vector3.left,
    };

    private void StartJump()
    {
        _jumpStart = transform.position;
        Vector3 jumpDir = GetBestCardinalDirection();           // ①
        _jumpEnd = _jumpStart + jumpDir * _jumpDistance;

        if (!CanMoveTo(_jumpEnd))
        {
            bool found = false;
            foreach (Vector3 dir in GetOtherCardinalDirs(jumpDir))  // ②
            {
                Vector3 candidate = _jumpStart + dir * _jumpDistance;
                if (CanMoveTo(candidate))
                {
                    jumpDir = dir;
                    _jumpEnd = candidate;
                    found = true;
                    break;
                }
            }
            if (!found) { _jumpTimer = 0.5f; return; }
        }

        transform.rotation = Quaternion.LookRotation(jumpDir);
        _jumpProgress = 0f;
        _isJumping = true;
        State = EState.Jump;
    }

    private Vector3 GetBestCardinalDirection()
    {
        if (Target == null) return CARDINAL_DIRS[Random.Range(0, 4)];
        Vector3 toPlayer = (Target.position - transform.position).normalized;
        float maxDot = float.MinValue;
        Vector3 best = Vector3.forward;
        foreach (Vector3 dir in CARDINAL_DIRS)
        {
            float dot = Vector3.Dot(toPlayer, dir);             // ③
            if (dot > maxDot) { maxDot = dot; best = dir; }
        }
        return best;
    }

    // 착지 시 4방향 발사
    private void FireFourWay()
    {
        Vector3 spawnPos = new Vector3(transform.position.x, 1f, transform.position.z);
        foreach (Vector3 dir in CARDINAL_DIRS)
        {
            GameObject go = ObjectPool.Instance.Get(_projectilePrefab);
            go.transform.position = spawnPos;
            go.transform.rotation = Quaternion.LookRotation(dir);
            ProjectileBase proj = go.GetComponent<ProjectileBase>();
            if (proj != null) proj.Init(_projectileDamage);     // ④
        }
    }

    private IEnumerator FireAndReturn()
    {
        yield return new WaitForSeconds(_attackDelay);          // ⑤
        FireFourWay();
        yield return new WaitForSeconds(0.3f);
        if (State != EState.Die) State = EState.Idle;
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | `GetBestCardinalDirection()`으로 플레이어 방향과 내적이 가장 큰 4방향을 선택한다. 대각선으로 가지 않고 가장 가까운 직교 방향으로 점프한다 |
| ② | 최우선 방향이 막혀있으면 나머지 3방향을 Fisher-Yates 셔플로 섞어 순서대로 시도한다. 셔플로 패턴의 예측 불가능성을 유지한다 |
| ③ | `Vector3.Dot(toPlayer, dir)`로 플레이어 방향과 각 4방향의 유사도를 계산한다. 내적이 가장 큰 방향이 플레이어에 가장 가까운 직교 방향이다 |
| ④ | 4방향 투사체를 동시에 발사한다. `ObjectPool.Get()`으로 풀에서 가져와 성능을 유지한다 |
| ⑤ | 착지 후 0.2초 대기(착지 연출) → 4방향 발사 → 0.3초 후 Idle 복귀. 대기 시간으로 플레이어가 착지를 인지하고 회피할 틈을 준다 |

**AI 흐름:**
```
Idle (점프 타이머 카운트다운)
    │
    ▼ 타이머 <= 0
StartJump()
    ├── GetBestCardinalDirection()
    │   └── 플레이어 방향에 가장 가까운 4방향 선택
    ├── CanMoveTo 실패 → 나머지 3방향 시도
    └── Jump 상태 → 포물선 이동
         │
         ▼ 착지
State = Attack
    ├── 0.2초 대기 (착지 연출)
    ├── FireFourWay() → 4방향 투사체
    ├── 0.3초 후
    └── State = Idle → 타이머 리셋
```

## 공통 접촉 데미지

> **왜 weight 비교를 하는가?** 모든 몬스터가 플레이어를 밀 수 있으면, 작은 박쥐에게 밀리는 부자연스러운 상황이 발생한다. `_weight <= player.Weight` 체크로 **플레이어보다 가벼운 몬스터는 밀기를 수행하지 못하게** 하여, 골렘 같은 무거운 몬스터만 플레이어를 밀어내는 현실적인 물리 느낌을 구현한다.

```csharp
// 비겹침 몬스터: Collision으로 밀기
private void OnCollisionStay(Collision collision)
{
    PlayerController player = collision.gameObject.GetComponent<PlayerController>();
    if (player == null) return;
    if (_weight <= player.Weight) return;  // ① 가벼운 몬스터는 밀지 못함
    Vector3 pushDir = (player.transform.position - transform.position).normalized;
    player.Push(pushDir * (_weight - player.Weight) * 0.5f * Time.deltaTime);  // ②
}

// 겹침 몬스터: Trigger로 데미지
private void OnTriggerStay(Collider other)
{
    PlayerController player = other.GetComponent<PlayerController>();
    if (player == null) return;
    _contactDamageTimer -= Time.deltaTime;
    if (_contactDamageTimer > 0f) return;  // 쿨다운
    player.TakeDamage(_damage);
    _contactDamageTimer = _contactDamageCooldown;
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | 몬스터 무게가 플레이어 이하이면 밀기를 수행하지 않는다. 작은 박쥐에게 밀리는 부자연스러운 상황을 방지한다 |
| ② | 밀기 힘은 `(몬스터 무게 - 플레이어 무게) × 0.5`에 비례한다. 무게 차이가 클수록 강하게 밀리며, `deltaTime`을 곱해 프레임률에 독립적으로 동작한다 |
