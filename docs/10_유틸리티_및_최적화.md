## ObjectPool - 큐 기반 오브젝트 풀링

> `Assets/Scripts/Manager/ObjectPool.cs`

> **왜 60초 만료로 자동 정리하는가?** 전투 중에는 투사체가 대량으로 생성/반환되므로 풀이 커야 하지만, 전투가 끝나면 풀에 수십 개의 비활성 오브젝트가 메모리를 점유한다. 60초 타이머로 미사용 오브젝트를 자동 삭제하면 **전투 중에는 풀의 이점을 누리면서, 유휴 상태에서는 메모리를 회수**할 수 있다. 영구 보관하면 스테이지가 진행될수록 메모리 사용량이 단조 증가한다.

> **왜 프리팹 이름을 키로 사용하는가?** `Instantiate()`로 생성된 오브젝트는 이름 뒤에 "(Clone)"이 붙는다. `obj.name = prefab.name`으로 Clone 접미사를 제거하면, **동일 프리팹에서 생성된 모든 인스턴스가 같은 키를 공유**하여 풀에서 정확히 매칭된다. InstanceID는 인스턴스마다 다르므로 풀링 키로 부적합하다.

```csharp
public class ObjectPool : Singleton<ObjectPool>
{
    private struct PoolItem
    {
        public GameObject obj;
        public float returnTime;  // 반환 시각 (만료 판정용)
    }

    private readonly Dictionary<string, Queue<PoolItem>> _pools = new();
    private readonly Dictionary<GameObject, string> _keyMap = new();
    private const float CLEANUP_INTERVAL = 60f;  // 1분마다 정리
    private const float EXPIRE_TIME = 60f;        // 반환 후 1분 경과 시 삭제

    private void Start()
    {
        StartCoroutine(CleanupRoutine());
    }

    /// 풀에서 오브젝트를 꺼낸다. 없으면 새로 생성한다.
    public GameObject Get(GameObject prefab)
    {
        string key = prefab.name;  // 프리팹 이름을 키로 사용

        if (_pools.TryGetValue(key, out Queue<PoolItem> queue))
        {
            while (queue.Count > 0)
            {
                PoolItem item = queue.Dequeue();
                if (item.obj != null)  // 외부에서 Destroy된 경우 스킵
                {
                    item.obj.SetActive(true);
                    return item.obj;
                }
            }
        }

        // 풀에 없으면 새로 생성
        GameObject obj = Instantiate(prefab);
        obj.name = prefab.name;  // ① "(Clone)" 제거하여 키 일관성 유지
        _keyMap[obj] = key;
        return obj;
    }

    /// 오브젝트를 비활성화하고 풀에 반환한다.
    public void Return(GameObject obj)
    {
        if (obj == null) return;
        obj.SetActive(false);

        if (!_keyMap.TryGetValue(obj, out string key))
        {
            Destroy(obj);  // 풀에서 관리하지 않는 오브젝트
            return;
        }

        if (!_pools.ContainsKey(key))
            _pools[key] = new Queue<PoolItem>();

        _pools[key].Enqueue(new PoolItem { obj = obj, returnTime = Time.time });
    }

    /// 1분마다 만료된 오브젝트를 삭제한다.
    private IEnumerator CleanupRoutine()
    {
        WaitForSeconds wait = new WaitForSeconds(CLEANUP_INTERVAL);

        while (true)
        {
            yield return wait;

            foreach (var kvp in _pools)
            {
                Queue<PoolItem> queue = kvp.Value;
                int count = queue.Count;

                for (int i = 0; i < count; i++)
                {
                    PoolItem item = queue.Dequeue();
                    if (item.obj == null) continue;

                    if (Time.time - item.returnTime >= EXPIRE_TIME)  // ②
                    {
                        _keyMap.Remove(item.obj);
                        Destroy(item.obj);  // 1분 이상 미사용 → 메모리 해제
                    }
                    else
                    {
                        queue.Enqueue(item);  // ③ 아직 유효 → 재삽입
                    }
                }
            }
        }
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | `Instantiate()`가 붙이는 "(Clone)" 접미사를 제거한다. 프리팹 원본 이름을 풀링 키로 사용하므로, Clone이 붙으면 키가 달라져 풀에서 매칭되지 않는다 |
| ② | 반환 시각과 현재 시각의 차이가 `EXPIRE_TIME`(60초)을 넘으면, 오래 미사용된 오브젝트로 판단하여 Destroy한다. 전투 종료 후 불필요한 메모리를 자동 회수한다 |
| ③ | 만료되지 않은 오브젝트는 큐에 다시 넣어 풀에 유지한다. Dequeue→검사→Enqueue 패턴으로 큐 전체를 순회한다 |

### 풀링 흐름

```
Get(prefab)
    ├── _pools[prefab.name] 큐에서 Dequeue
    │   ├── obj != null → SetActive(true) → 반환
    │   └── obj == null → 스킵 (다음 시도)
    └── 큐 비어있음 → Instantiate(prefab) → _keyMap 등록 → 반환

Return(obj)
    ├── SetActive(false)
    └── _pools[key].Enqueue({ obj, Time.time })

CleanupRoutine (60초마다)
    └── 각 큐 순회: returnTime + 60 < Time.time → Destroy
```

### 풀링 대상

| 오브젝트 | 생성 빈도 | 설명 |
|---------|----------|------|
| PlayerProjectile | 매 공격 × 방향 수 × FrontArrow | 가장 빈번 |
| MonsterProjectile | 몬스터 공격 시 | 중간 |
| DamageText | 매 피격 | 빈번 |
| FireExplosion | 파이어볼 폭발 시 | 간헐적 |

## AudioManager - 3채널 오디오

> `Assets/Scripts/Manager/AudioManager.cs`

> **왜 3개 채널로 분리하는가?** 레벨업이나 장비창에서 `TimeScale=0`이 되면 일반 AudioSource가 정지한다. 하지만 UI 버튼 클릭음이나 룰렛 사운드는 TimeScale과 무관하게 재생되어야 한다. UI SFX 채널에 `ignoreListenerPause = true`를 설정하면 **TimeScale=0 상태에서도 UI 효과음만 선별적으로 재생**할 수 있다. BGM, 게임 SFX, UI SFX를 분리하여 각각 독립적으로 볼륨 조절과 일시정지가 가능하다.

```csharp
public class AudioManager : Singleton<AudioManager>
{
    // Inspector에서 할당하는 AudioClip들
    [SerializeField] private AudioClip _footstepClip;
    [SerializeField] private AudioClip _bgmClip;
    [SerializeField] private AudioClip _hitClip;
    [SerializeField] private AudioClip _playerProjectileClip;
    [SerializeField] private AudioClip _monsterProjectileClip;
    [SerializeField] private AudioClip _buttonClickClip;
    [SerializeField] private AudioClip _levelUpClip;
    [SerializeField] private AudioClip _expCollectClip;
    [SerializeField] private AudioClip _upgradeSlotSpinClip;
    [SerializeField] private AudioClip _upgradeSlotConfirmClip;
    [SerializeField] private AudioClip _stageProgressClip;
    [SerializeField] private AudioClip _upgradePanelOpenClip;

    // 3개의 독립 AudioSource
    private AudioSource _bgmSource;     // BGM (loop)
    private AudioSource _sfxSource;     // 게임 효과음
    private AudioSource _uiSfxSource;   // UI 효과음 (ignoreListenerPause)

    private void Awake()
    {
        _bgmSource = gameObject.AddComponent<AudioSource>();
        _bgmSource.loop = true;
        _bgmSource.playOnAwake = false;

        _sfxSource = gameObject.AddComponent<AudioSource>();
        _sfxSource.playOnAwake = false;

        _uiSfxSource = gameObject.AddComponent<AudioSource>();
        _uiSfxSource.playOnAwake = false;
        _uiSfxSource.ignoreListenerPause = true;  // TimeScale=0에서도 재생
    }

    // 각 사운드별 PlayOneShot 래퍼
    public void PlayBGM() { ... }
    public void PlayFootstep() { ... }
    public void PlayHit() { ... }
    public void PlayPlayerProjectile() { ... }
    public void PlayMonsterProjectile() { ... }
    public void PlayButtonClick() { ... }
    public void PlayLevelUp() { ... }
    public void PlayExpCollect() { ... }
    public void PlayUpgradeSlotSpin() { ... }
    public void PlayUpgradeSlotConfirm() { ... }
    public void PlayStageProgress() { ... }
    public void PlayUpgradePanelOpen() { ... }
}
```

### 3채널 설계

| 채널 | AudioSource | 특징 | 사용처 |
|------|------------|------|--------|
| **BGM** | `_bgmSource` | loop=true | 배경 음악 |
| **SFX** | `_sfxSource` | PlayOneShot | 발소리, 피격, 투사체, 경험치 |
| **UI SFX** | `_uiSfxSource` | ignoreListenerPause | 버튼, 레벨업, 업그레이드 |

### 설계 의도

- **UI SFX 분리**: `ignoreListenerPause = true`로 TimeScale=0 상태(레벨업, 장비창)에서도 UI 효과음 재생
- **Null-safe 호출**: 모든 호출부에서 `AudioManager.Instance?.PlayXxx()` 패턴으로 null 안전 보장

## CameraController - 아이소메트릭 카메라

> `Assets/Scripts/Controllers/CameraController.cs`

```csharp
public class CameraController : MonoBehaviour
{
    public static CameraController Instance { get; private set; }

    [SerializeField] private Transform _target;
    [SerializeField] private Vector3 _offset = new Vector3(0f, 10f, 0f);
    [SerializeField] private Vector3 _rotation = new Vector3(90f, 0f, 0f);

    private float _shakeTimer;
    private float _shakeMagnitude;

    private void Awake() { Instance = this; }

    public void Shake(float duration, float magnitude)
    {
        if (GameManager.Instance != null && GameManager.Instance.IsPaused) return;
        _shakeTimer = duration;
        _shakeMagnitude = magnitude;
    }

    void LateUpdate()
    {
        if (_target == null)
        {
            // 자동 타겟 탐색
            PlayerController player = FindAnyObjectByType<PlayerController>();
            if (player != null) _target = player.transform;
            return;
        }

        // 플레이어 추적
        transform.position = _target.position + _offset;

        // 카메라 쉐이크
        if (_shakeTimer > 0f)
        {
            if (GameManager.Instance != null && GameManager.Instance.IsPaused)
                _shakeTimer = 0f;  // 일시정지 시 즉시 중단
            else
            {
                transform.position += Random.insideUnitSphere * _shakeMagnitude;  // ①
                _shakeTimer -= Time.deltaTime;
            }
        }

        // 플레이어를 바라봄 (탑뷰)
        transform.LookAt(_target);  // ②
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | 단위 구 내부의 랜덤 점에 흔들림 크기를 곱하여, 매 프레임 카메라 위치를 무작위로 살짝 이동시킨다. 3축 모두에 랜덤이 적용되어 자연스러운 화면 흔들림이 된다 |
| ② | 카메라가 항상 플레이어를 바라보도록 `LookAt`을 호출한다. 쉐이크로 위치가 미세하게 변해도 시선 방향이 보정되어 화면 중심이 유지된다 |

### 설계 의도

> **왜 `Singleton<T>`를 쓰지 않는가?** `Singleton<T>`는 인스턴스가 없으면 자동 생성하는 Lazy Init 패턴이다. 하지만 카메라는 **씬에 반드시 존재하는 오브젝트**이므로, 자동 생성 로직이 불필요하다. 코드로 생성된 카메라는 Transform, Culling Mask 등의 설정이 빠져있어 정상 동작하지 않는다. 따라서 단순한 `static Instance`로 Awake()에서 할당하는 것이 더 적합하다.

- **독립 싱글톤**: `Singleton<T>` 대신 직접 `static Instance` (씬에 반드시 1개 존재, 자동 생성 불필요)
- **LateUpdate**: 플레이어 이동 후 카메라 갱신하여 지터 방지
- **Pause-safe Shake**: 일시정지 상태에서 쉐이크 즉시 중단

## SpriteAtlasBinder - SpriteAtlas V2 런타임 바인딩

> `Assets/Scripts/Manager/SpriteAtlasBinder.cs`

> **왜 런타임 바인딩이 필요한가?** Unity SpriteAtlas V2는 "Late Binding" 방식으로 동작한다. 에디터에서는 아틀라스가 자동 바인딩되지만, **빌드에서는 `SpriteAtlasManager.atlasRequested` 콜백을 통해 수동으로 아틀라스를 제공**해야 한다. 이 콜백을 등록하지 않으면 빌드에서 모든 아틀라스 스프라이트가 흰색으로 표시되는 문제가 발생한다.

```csharp
public static class SpriteAtlasBinder
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Init()                                         // ①
    {
        SpriteAtlasManager.atlasRequested += OnAtlasRequested;
    }

    static void OnAtlasRequested(string tag, System.Action<SpriteAtlas> callback)
    {
        SpriteAtlas atlas = Resources.Load<SpriteAtlas>($"UI/{tag}");  // ②
        if (atlas != null)
            callback(atlas);                                    // ③
        else
            Debug.LogWarning($"[SpriteAtlasBinder] SpriteAtlas not found: UI/{tag}");
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | `[RuntimeInitializeOnLoadMethod(BeforeSceneLoad)]`로 어떤 씬보다 먼저 실행된다. MonoBehaviour가 아닌 static 클래스이므로 씬 배치나 프리팹이 불필요하다 |
| ② | 아틀라스 태그명으로 `Resources/UI/` 폴더에서 SpriteAtlas를 로드한다. 태그명은 Unity가 자동으로 아틀라스 이름으로 설정한다 |
| ③ | 콜백에 로드한 아틀라스를 전달하면 Unity가 내부적으로 스프라이트를 아틀라스에 바인딩한다 |

### SpriteAtlas Late Binding 흐름

```
앱 시작 (BeforeSceneLoad)
    │
    ▼
SpriteAtlasBinder.Init()
    └── atlasRequested 이벤트 구독
         │
         ▼ UI Image 렌더링 시
    Unity: "Icon 아틀라스 필요"
         │
         ▼
    OnAtlasRequested("Icon", callback)
         ├── Resources.Load<SpriteAtlas>("UI/Icon")
         └── callback(atlas)  → 바인딩 완료
```

## IconHelper - 듀얼 아틀라스 스프라이트 로딩

> `Assets/Scripts/Utils/IconHelper.cs`

> **왜 두 개의 아틀라스를 사용하는가?** 스킬 아이콘은 "Icon" 아틀라스에, 등급 배경/공통 UI 요소는 "Common" 아틀라스에 분리되어 있다. 하나의 거대한 아틀라스 대신 **용도별로 분리하면 메모리 효율이 높아진다.** 스킬 관련 UI만 표시할 때는 Icon 아틀라스만 로드되고, Common은 필요 시에만 lazy-load된다.

```csharp
public static class IconHelper
{
    private static SpriteAtlas _atlas;                         // ① Icon 아틀라스
    private static SpriteAtlas _commonAtlas;                   // ② Common 아틀라스

    public static Sprite GetSprite(string name)
    {
        if (_atlas == null)
            _atlas = Resources.Load<SpriteAtlas>("UI/Icon");   // ③ Lazy Load

        Sprite sprite = _atlas != null ? _atlas.GetSprite(name) : null;

        if (sprite == null)                                     // ④ Fallback
        {
            if (_commonAtlas == null)
                _commonAtlas = Resources.Load<SpriteAtlas>("UI/Common");
            sprite = _commonAtlas != null ? _commonAtlas.GetSprite(name) : null;
        }

        return sprite;
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | "Icon" 아틀라스를 static 필드에 캐싱한다. 한 번 로드하면 앱 종료까지 유지된다 |
| ② | "Common" 아틀라스도 별도 캐싱한다. Icon에서 못 찾을 때만 참조된다 |
| ③ | 최초 호출 시에만 `Resources.Load`로 아틀라스를 로드한다. 이후 호출은 캐싱된 아틀라스에서 O(1)로 스프라이트를 조회한다 |
| ④ | Icon 아틀라스에서 스프라이트를 못 찾으면 Common 아틀라스에서 재탐색한다. 등급 배경(`GradeBg_Common` 등)이 여기서 발견된다 |

### 스프라이트 조회 흐름

```
GetSprite("GradeBg_Rare")
    │
    ├── _atlas (Icon) 에서 탐색
    │   └── 없음 (스킬 아이콘만 포함)
    │
    ├── _commonAtlas (Common) 에서 탐색
    │   └── 발견! → 반환
    │
    └── 두 곳 모두 없음 → null 반환
```

## 성능 최적화 사례 정리

### 1. Dictionary 캐시

| 위치 | 기존 | 최적화 | 효과 |
|------|------|--------|------|
| TileMap.GetTile() | List O(n) 순회 | Dictionary O(1) 조회 | 타일 조회 속도 향상 |
| TileMap.GetBlockIndex() | List O(n) 순회 | Dictionary O(1) 조회 | 블록 조회 속도 향상 |
| Define._gradeSpriteCache | 매번 Resources.Load | Dictionary 캐시 | Sprite 로드 1회로 제한 |

### 2. Greedy Rectangle Merge

| 위치 | 기존 | 최적화 | 효과 |
|------|------|--------|------|
| TileMap Wall/Water 콜라이더 | 타일당 1개 BoxCollider | Greedy Merge → 최소 BoxCollider | 물리 연산 부하 대폭 감소 |
| TileMap Floor 콜라이더 | 타일당 1개 BoxCollider | 전체 맵 1개 BoxCollider | 극한 최적화 |

### 3. A* 경로탐색 최적화

| 기법 | 구현 | 효과 |
|------|------|------|
| **Dirty Flag** | 플레이어 그리드 변경 시에만 `_pathDirty = true` | 불필요한 A* 실행 방지 |
| **Timer** | 0.5초 인터벌로 갱신 빈도 제한 | 매 프레임 A* 방지 |
| **SortedSet** | `SortedSet<(fCost, hCost, x, y)>` | O(log n) 삽입/최소 조회 |
| **이동 불가 목표 대체** | 벽 목표 → 인접 이동 가능 타일 | 탐색 실패 감소 |

### 5. ObjectPool 자동 정리

```
활발한 전투 → 투사체 50개 풀링
    │
    ▼ 전투 종료 → 1분 미사용
CleanupRoutine → Destroy → 메모리 회수
```


> **왜 런타임에 Static Batching을 Combine하는가?** Static Batching은 보통 에디터에서 오브젝트를 "Static"으로 체크하면 빌드 시 자동 적용된다. 하지만 이 게임의 타일 바닥과 배경 블록은 **TileMap에서 런타임에 동적 생성**되므로, 에디터 시점에는 존재하지 않는다. `StaticBatchingUtility.Combine()`을 런타임에 호출하여 동적 생성된 오브젝트에도 배칭을 적용한다.

### 6. Static Batching

```csharp
// TileMap.GenerateVisuals() 마지막
container.gameObject.isStatic = true;
StaticBatchingUtility.Combine(container.gameObject);
// 타일 바닥, 배경 블록 등 정적 오브젝트 일괄 배칭
```

### 7. 개별 콜라이더 제거

```csharp
// 타일 바닥 큐브의 개별 BoxCollider 제거 (단일 FloorCollider로 대체)
Object.DestroyImmediate(floor.GetComponent<BoxCollider>());
```

### 8. 풀링 + 코루틴 수명 관리

```csharp
// ProjectileBase: 풀 반환 시 코루틴 정리
private void ReturnToPool()
{
    if (_lifeCoroutine != null)
    {
        StopCoroutine(_lifeCoroutine);
        _lifeCoroutine = null;
    }
    ObjectPool.Instance.Return(gameObject);
}
```
