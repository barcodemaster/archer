# 03. 업그레이드 시스템

## 개요

레벨업마다 3개의 업그레이드를 랜덤 제안하고, 선택 시 플레이어를 강화하는 시스템입니다.
CSV 기반 데이터 드리븐 설계로, 코드 변경 없이 밸런스를 조정할 수 있습니다.

---

## 데이터 흐름

```
Resources/Data/UpgradeData.csv
        │
        ▼ (Resources.Load → 헤더 기반 파싱)
UpgradeDatabase (static)
    ├── GetAll() → UpgradeInfo[]
    ├── GetInfo(type) → UpgradeInfo
    └── PickRandom(3) → 만렙 제외 랜덤 3개
        │
        ▼
UI_LevelUp (룰렛 연출)
    ├── 3개 슬롯에 표시
    └── 선택 시:
        │
        ▼
PlayerUpgrade.AddUpgrade(type)  ← 레벨 증가
PlayerController.ApplyUpgradeEffect(type)  ← 즉시 효과
```

## UpgradeDatabase - CSV 파싱

> **왜 ScriptableObject 대신 CSV인가?** ScriptableObject는 Unity 에디터에서만 편집 가능하고, 22개 업그레이드의 밸런스 수치를 하나하나 Inspector에서 수정하는 것은 비효율적이다. CSV는 Excel/Google Sheets에서 편집 후 그대로 넣으면 되므로, **기획자가 코드를 건드리지 않고 밸런스를 조정할 수 있다.** 빌드 후에도 Resources 폴더에서 런타임 로드가 가능하다.

> `Assets/Scripts/Upgrade/UpgradeDatabase.cs`

```csharp
public class UpgradeInfo
{
    public EUpgradeType type;
    public string name;
    public string description;
    public Sprite icon;
    public int maxLevel = 1;

    // 스탯 필드 (CSV 컬럼과 1:1 매핑)
    public float attack;
    public float attackPercent;
    public float attackSpeed;
    public float critRate;
    public float critDamage;
    public float critDamageBase;
    public float critDamageRange;
    public float maxHp;
    public float healAmount;
    public float scale;
    public float probability;
    public float maxLevelCap;
    public float frontArrow;
    public float multiShotDelay;
    public float ricochetRadius;
    public float attackPerHpPercent;
    public float enemySlowPercent;
}

public static class UpgradeDatabase
{
    private static UpgradeInfo[] _all;

    private static void Init()
    {
        if (_all != null) return;

        // CSV 로드 및 헤더 기반 파싱
        TextAsset csv = Resources.Load<TextAsset>("Data/UpgradeData");
        string[] lines = csv.text.Split('\n');
        List<UpgradeInfo> list = new();

        string[] headers = SplitCsvLine(lines[0].Trim());
        Dictionary<string, int> headerMap = new();  // ①
        for (int h = 0; h < headers.Length; h++)
            headerMap[headers[h].Trim()] = h;

        for (int i = 1; i < lines.Length; i++)
        {
            string line = lines[i].Trim();
            if (string.IsNullOrEmpty(line)) continue;
            string[] cols = SplitCsvLine(line);

            var info = new UpgradeInfo
            {
                type = System.Enum.Parse<EUpgradeType>(GetCol(cols, headerMap, "type")),
                name = GetCol(cols, headerMap, "name"),
                description = GetCol(cols, headerMap, "description"),
                icon = IconHelper.GetSprite(GetCol(cols, headerMap, "icon")),
                maxLevel = int.TryParse(GetCol(cols, headerMap, "maxLevel"), out int ml)
                    ? ml : 1,
                // ... 각 스탯 필드 파싱 (GetFloat)
            };
            list.Add(info);
        }
        _all = list.ToArray();
    }

    // 만렙 업그레이드를 제외하고 랜덤 3개 선택
    public static List<UpgradeInfo> PickRandom(int count)
    {
        Init();
        List<UpgradeInfo> pool = new();

        PlayerUpgrade playerUpgrade = Object.FindAnyObjectByType<PlayerUpgrade>();
        foreach (var info in _all)
        {
            // 이미 만렙인 업그레이드 제외
            if (playerUpgrade != null
                && playerUpgrade.GetLevel(info.type) >= info.maxLevel)  // ②
                continue;
            pool.Add(info);
        }

        // Fisher-Yates 스타일 랜덤 선택
        List<UpgradeInfo> result = new();
        for (int i = 0; i < count && pool.Count > 0; i++)
        {
            int idx = Random.Range(0, pool.Count);
            result.Add(pool[idx]);
            pool.RemoveAt(idx);  // ③
        }
        return result;
    }

    // CSV 따옴표 안의 쉼표를 무시하는 파서
    private static string[] SplitCsvLine(string line) { ... }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | CSV 첫 행(헤더)을 Dictionary로 변환하여, 이후 컬럼 접근 시 `headerMap["attackSpeed"]`처럼 이름으로 인덱스를 조회한다. 컬럼 순서가 바뀌어도 파싱이 깨지지 않는다 |
| ② | 플레이어가 이미 해당 업그레이드의 최대 레벨에 도달했으면 선택지 풀에서 제외한다. 만렙 업그레이드가 반복 제안되는 것을 방지한다 |
| ③ | 선택한 항목을 풀에서 즉시 제거하여 중복 선택을 방지한다. Fisher-Yates 방식의 비복원 추출이다 |

### 설계 의도

> **왜 인덱스가 아닌 헤더 이름으로 매핑하는가?** `cols[3]`처럼 인덱스로 접근하면, CSV에 컬럼을 하나 추가하거나 순서를 바꿀 때 파싱 코드 전체를 수정해야 한다. 헤더 이름 기반 매핑(`headerMap["attackSpeed"]`)은 **컬럼 순서 변경에 완전히 안전**하므로, 기획자가 CSV 구조를 자유롭게 수정할 수 있다.

- **Lazy Init**: 최초 접근 시 한 번만 파싱, 이후 메모리 캐시
- **헤더 기반 파싱**: 컬럼 순서가 바뀌어도 정상 동작 (Dictionary 매핑)
- **따옴표 처리**: description에 쉼표가 포함될 수 있어 `SplitCsvLine`에서 인용부호 안의 쉼표를 무시

## 업그레이드 분류표

### 공격 방향 업그레이드

| 타입 | 최대레벨 | 효과 | 스케일링 공식 |
|------|---------|------|--------------|
| FrontArrow | N | 전방 화살 +1개 (평행 오프셋 0.4f) | `totalCount = 1 + level` |
| DiagonalArrow | 1 | ±45° 방향 추가 | 활성화/비활성화 |
| SideArrow | 1 | ±90° 방향 추가 | 활성화/비활성화 |
| BackArrow | 1 | 180° 방향 추가 | 활성화/비활성화 |

### 공격 옵션 업그레이드

| 타입 | 최대레벨 | 효과 | 스케일링 공식 |
|------|---------|------|--------------|
| MultiShot | N | 추가 발리 (딜레이) | `반복 = level, 딜레이 = CSV.multiShotDelay` |
| Piercing | 1 | 관통 (무한 히트) | 활성화/비활성화 |
| WallBounce | 1 | 벽 반사 | SphereCast로 BlockObstacle 반사 |
| Ricochet | N | 적 간 도탄 | `횟수 = level, 반경 = CSV.ricochetRadius` |
| Headshot | N | 즉사 확률 | `chance = level × (CSV.probability / 100)` |

### 스탯 업그레이드

| 타입 | 최대레벨 | 효과 | 스케일링 공식 |
|------|---------|------|--------------|
| AttackSpeed | N | 공격속도 증가 | `1 + level × (CSV.attackSpeed / 100)` |
| AttackBoost | N | 공격력 증가 | `1 + level × (CSV.attackPercent / 100)` |
| CriticalMaster | N | 크리티컬 확률/배율 | `확률 = level × (CSV.critRate / 100)` |
| | | | `최소배율 = CSV.critDamageBase/100 + level × (CSV.critDamage/100)` |
| | | | `최대배율 = 최소배율 + CSV.critDamageRange/100` |
| HpBoost | N | 최대HP 증가+즉시회복 | `maxHp += maxHp × (CSV.maxHp/100), heal = 추가분 × (CSV.healAmount/100)` |

### 특수 업그레이드

| 타입 | 최대레벨 | 효과 | 스케일링 공식 |
|------|---------|------|--------------|
| Rage | 1 | 잃은 HP%만큼 공격력↑ | `dmg × (1 + missingHP% × CSV.attackPerHpPercent / 100)` |
| ExtraLife | 1 | 1회 부활 (HP 풀회복) | 소비형 (1회) |
| FastGrowth | 1 | 최대 레벨 상향 + 경험치 1.5배 | `maxLevel = CSV.maxLevelCap` |
| SlowProjectile | N | 적 투사체 감속 | `speed × (1 - level × CSV.enemySlowPercent / 100)` |
| BloodThirst | N | 처치 시 HP 회복 | `heal = maxHp × level × (CSV.healAmount / 100)` |

### 이동/패시브 업그레이드

| 타입 | 최대레벨 | 효과 | 구현 방식 |
|------|---------|------|----------|
| WallPass | 1 | 장애물 통과 | `TilePassability += WallPass`, BlockObstacle.isTrigger = true |
| WaterWalker | 1 | 수면 보행 | `TilePassability += WaterWalk`, WaterObstacle.isTrigger = true |
| Dwarf | 1 | 축소 + 크리티컬↑ | `scale × CSV.scale`, 크리티컬 확률/배율 추가 |
| Giant | 1 | 확대 + 공격력↑ | `scale × CSV.scale`, `dmg × (1 + CSV.attackPercent/100)` |

## 주요 스케일링 공식 상세

> **스케일링 공식 설계 철학:** 각 업그레이드의 스케일링은 의도적으로 선형(additive)과 곱연산(multiplicative)을 구분했다. **공격속도와 크리티컬은 선형 누적**(`1 + level × rate`)으로, 레벨이 올라도 체감 증가폭이 일정하여 과도한 파워 인플레이션을 방지한다. 반면 **분노(Rage)는 곱연산**(`dmg × (1 + bonus)`)으로, 위험을 감수한 만큼 폭발적인 보상을 준다. 이런 공식 차이가 "안정적 성장" vs "하이리스크 하이리턴" 빌드 다양성을 만든다.

### 공격속도

```csharp
public float AttackSpeedMultiplier
{
    get
    {
        var i = Info(EUpgradeType.AttackSpeed);
        return 1f + _attackSpeedLevel * (i?.attackSpeed ?? 15f) / 100f;
    }
}
// 예: lv3, CSV.attackSpeed=15 → 1 + 3 × 15/100 = 1.45배
```

### 크리티컬 시스템

```csharp
// 확률 = CriticalMaster 레벨 기여 + Dwarf 보너스
public float CritChance
{
    get
    {
        var cm = Info(EUpgradeType.CriticalMaster);
        var dw = Info(EUpgradeType.Dwarf);
        return _criticalMasterLevel * (cm?.critRate ?? 5f) / 100f
            + (_dwarfLevel > 0 ? (dw?.critRate ?? 5f) / 100f : 0f);
    }
}

// 최소 배율 = 기본값 + 레벨 스케일링 + Dwarf 보너스
public float CritDamageMin
{
    get
    {
        var cm = Info(EUpgradeType.CriticalMaster);
        var dw = Info(EUpgradeType.Dwarf);
        return (cm?.critDamageBase ?? 150f) / 100f       // ① 기본 1.5배
            + _criticalMasterLevel * (cm?.critDamage ?? 10f) / 100f  // ②
            + (_dwarfLevel > 0 ? (dw?.critDamage ?? 10f) / 100f : 0f);
    }
}

// 최대 배율 = 최소 + 범위
public float CritDamageMax
{
    get
    {
        var cm = Info(EUpgradeType.CriticalMaster);
        return CritDamageMin + (cm?.critDamageRange ?? 10f) / 100f;  // ③
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | `critDamageBase`가 150이면 `/100f` 후 1.5배가 된다. 크리티컬 미투자 시에도 기본 1.5배 배율을 보장하여 크리티컬이 항상 의미 있는 보상이 된다 |
| ② | 레벨당 `critDamage/100`만큼 선형으로 최소 배율이 증가한다. 예: lv3, critDamage=10이면 +0.3 → 최소 1.8배 |
| ③ | 최대 배율 = 최소 배율 + 고정 범위. 범위가 10이면 최소~최소+0.1 사이에서 랜덤이 결정되어, 크리티컬 데미지에 약간의 변동성을 부여한다 |
