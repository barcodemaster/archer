## PlayerController 전체 코드

using System.Collections.Generic;

## 이동 시스템

### 아이소메트릭 45도 회전

> **왜 `Quaternion.Euler(0, 45, 0)` 보정이 필요한가?** 이 게임의 카메라는 아이소메트릭(등각) 시점으로, Y축 기준 45도 회전되어 있다. 조이스틱 입력은 화면 기준 상/하/좌/우인데, 월드 좌표에서는 카메라가 45도 틀어져 있으므로 "화면 위쪽"이 월드의 (0,0,1)이 아닌 대각선 방향이 된다. 이 보정이 없으면 **조이스틱을 위로 밀었는데 캐릭터가 대각선으로 이동하는** 직관에 맞지 않는 동작이 발생한다.

```csharp
void Update()
{
    if (GameManager.Instance.IsPaused) return;
    if (_state == EState.Die) return;

    Vector3 dir = GameManager.Instance.JoystickDir;  // UI에서 전달된 2D 방향
    Vector3 moveDir = new Vector3(dir.x, 0, dir.y);

    // 핵심: 카메라가 45도 회전되어 있으므로 이동 방향도 45도 보정
    moveDir = (Quaternion.Euler(0, 45, 0) * moveDir).normalized;  // ①

    if (moveDir != Vector3.zero)
    {
        _controller.Move(moveDir * Time.deltaTime * _moveSpeed);

        // 부드러운 회전
        Quaternion lookRotation = Quaternion.LookRotation(moveDir);
        transform.rotation = Quaternion.RotateTowards(
            transform.rotation, lookRotation, Time.deltaTime * _rotateSpeed);  // ②

        _attackTarget = null;  // ③ 이동 중에는 공격 취소
        State = EState.Move;

        // 발소리 재생
        _footstepTimer -= Time.deltaTime;
        if (_footstepTimer <= 0f)
        {
            AudioManager.Instance?.PlayFootstep();
            _footstepTimer = FOOTSTEP_INTERVAL;
        }
    }
    ...
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | 카메라가 Y축 45도 회전된 아이소메트릭 뷰이므로, 조이스틱 입력 벡터도 동일하게 45도 회전시켜 화면 기준 방향과 월드 이동 방향을 일치시킨다 |
| ② | 즉시 회전(`LookRotation`) 대신 `RotateTowards`로 매 프레임 최대 `_rotateSpeed`도씩 회전하여, 방향 전환이 부드럽게 보간된다 |
| ③ | 이동을 시작하면 기존 공격 타겟을 해제하여, 이동과 공격이 동시에 발생하지 않도록 상태를 정리한다 |

## 자동 공격 시스템

### 가장 가까운 몬스터 탐색

> **왜 매 프레임 전체 탐색(O(n))인가?** 공간 분할(쿼드트리 등)이나 캐싱으로 최적화할 수 있지만, 이 게임에서는 동시 존재 몬스터가 최대 20~30마리 수준이므로 O(n) 전체 탐색의 비용이 무시할 만하다. 캐싱하면 몬스터 사망/스폰 시 캐시 무효화 처리가 필요해 오히려 복잡도만 높아진다. **간단한 구현으로 항상 정확한 결과를 보장하는 것**이 소규모 풀에서는 더 현명한 선택이다.

```csharp
private MonsterBase FindClosestMonster()
{
    MonsterBase[] monsters = FindObjectsByType<MonsterBase>(FindObjectsSortMode.None);
    MonsterBase closest = null;
    float minDist = float.MaxValue;

    foreach (MonsterBase m in monsters)
    {
        if (m.CurrentHp <= 0) continue;  // 죽은 몬스터 무시

        float dist = Vector3.Distance(transform.position, m.transform.position);
        if (dist < minDist)
        {
            minDist = dist;
            closest = m;
        }
    }
    return closest;
}
```

### 공격 애니메이션 동기화

> **왜 `normalizedTime` 기반 발사 타이밍인가?** Unity에서 공격 타이밍을 구현하는 방법은 크게 두 가지다: (1) 애니메이션 이벤트, (2) normalizedTime 기반 체크. 애니메이션 이벤트는 직관적이지만, 공격 속도가 업그레이드로 변하면 이벤트 타이밍이 어색해지거나 씹힐 수 있다. `normalizedTime`은 **애니메이션 속도와 무관하게 항상 30% 지점에서 발사**되므로, 공격속도 업그레이드가 적용되어도 발사 타이밍의 비율이 유지된다.

```csharp
// 조이스틱 릴리즈 → 정지 상태 → 공격 시작
else  // moveDir == Vector3.zero
{
    MonsterBase target = FindClosestMonster();
    if (target != null)
    {
        _attackTarget = target;

        // 항상 몬스터 방향으로 회전
        Vector3 lookDir = (target.transform.position - transform.position).normalized;
        lookDir.y = 0;
        if (lookDir != Vector3.zero)
            transform.rotation = Quaternion.LookRotation(lookDir);

        if (_state != EState.Attack)
        {
            // 최초 진입: 애니메이션 시작
            _hasFired = false;
            _lastLoopIndex = 0;

            // 장비 공격속도 보너스 적용
            float equipAtkSpd = 1f + EquipmentManager.Instance
                .GetTotalSubStat(ESubStatType.AttackSpeed) / 100f;
            _animator.speed = _attackAnimSpeed
                * _upgrade.AttackSpeedMultiplier * equipAtkSpd;

            State = EState.Attack;
        }
        else
        {
            // 공격 애니메이션 루프 중 발사 타이밍 감지
            AnimatorStateInfo info = _animator.GetCurrentAnimatorStateInfo(0);
            if (info.shortNameHash == Define.ATTACK)
            {
                int loopIndex = Mathf.FloorToInt(info.normalizedTime);  // ①
                float loopProgress = info.normalizedTime % 1f;  // ②

                // 새 루프 진입 시 발사 플래그 리셋
                if (loopIndex > _lastLoopIndex)  // ③
                {
                    _hasFired = false;
                    _lastLoopIndex = loopIndex;
                }

                // 발사 타이밍 (0.3 = 애니메이션 30% 지점)
                if (!_hasFired && loopProgress >= _attackFireTime)  // ④
                {
                    _hasFired = true;
                    FireProjectile(_attackTarget);
                }
            }
        }
    }
    else
    {
        _attackTarget = null;
        State = EState.Idle;
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | `normalizedTime`의 정수부가 애니메이션이 몇 번째 루프인지를 나타낸다. 예: 2.3이면 3번째 루프(0-indexed) |
| ② | `normalizedTime`의 소수부가 현재 루프 내 진행률이다. 예: 2.3이면 현재 루프의 30% 지점 |
| ③ | `loopIndex`가 증가했다면 새 루프에 진입한 것이므로, `_hasFired`를 리셋하여 이번 루프에서 다시 발사할 수 있게 한다 |
| ④ | 현재 루프 진행률이 `_attackFireTime`(0.3 = 30%)을 넘었고 아직 미발사라면, 이 시점에 투사체를 발사한다 |

## 투사체 발리 시스템

### FireProjectile → MultiShotCoroutine → SpawnVolley → BuildDirections

> **왜 방향별 독립 벡터로 구현했는가?** 각 방향 업그레이드(Diagonal, Side, Back)가 독립적인 벡터 리스트를 구성하고, FrontArrow가 각 방향에 평행 복제를 적용하는 2단계 구조다. 이렇게 분리하면 새로운 방향 업그레이드를 추가할 때 `BuildDirections`에 한 줄만 추가하면 되고, FrontArrow 오프셋 로직은 수정할 필요가 없다. **관심사의 분리로 확장성을 확보**한 설계다.

```csharp
private void FireProjectile(MonsterBase target)
{
    Vector3 baseDir = target.transform.position - transform.position;
    baseDir.y = 0;
    baseDir.Normalize();

    AudioManager.Instance?.PlayPlayerProjectile();
    SpawnVolley(baseDir);

    // 멀티샷: 추가 발리를 딜레이로 발사
    if (_upgrade.MultiShotLevel > 0)
        StartCoroutine(MultiShotCoroutine(baseDir));
}

private IEnumerator MultiShotCoroutine(Vector3 baseDir)
{
    for (int i = 0; i < _upgrade.MultiShotLevel; i++)
    {
        yield return new WaitForSeconds(_upgrade.MultiShotDelay);
        if (_state == EState.Die) yield break;
        SpawnVolley(baseDir);
    }
}

private void SpawnVolley(Vector3 baseDir)
{
    List<Vector3> directions = BuildDirections(baseDir);

    // 최종 데미지 계산 (장비 + 업그레이드 누적)
    float baseDamage = _attackDamage + EquipmentManager.Instance.GetTotalAttackBonus();
    baseDamage *= _upgrade.AttackBoostMultiplier;  // 공격 부스트
    baseDamage *= _upgrade.GiantDamageMultiplier;  // 거인 보너스
    if (_upgrade.HasRage)  // 분노: 잃은 HP%만큼 공격력 증가
    {
        float missingHpPercent = (1f - _currentHp / _maxHp) * 100f;
        baseDamage *= 1f + missingHpPercent * _upgrade.RageAttackPerHpPercent / 100f;  // ③
    }

    // 장비 크리티컬 보너스
    float equipCritChance = EquipmentManager.Instance
        .GetTotalSubStat(ESubStatType.CritChance) / 100f;
    float equipCritDamage = EquipmentManager.Instance
        .GetTotalSubStat(ESubStatType.CritDamage) / 100f;

    // 투사체 초기화 데이터 구성
    ProjectileInitData data = new ProjectileInitData
    {
        damage = baseDamage,
        isPiercing = _upgrade.IsPiercing,
        headshotChance = _upgrade.HeadshotChance,
        wallBounce = _upgrade.IsWallBounce,
        ricochetCount = _upgrade.RicochetCount,
        ricochetRadius = _upgrade.RicochetRadius,
        critChance = _upgrade.CritChance + equipCritChance,  // ④
        critDamageMin = _upgrade.CritDamageMin + equipCritDamage,
        critDamageMax = _upgrade.CritDamageMax + equipCritDamage,
    };

    // 각 방향에 대해 전방화살 오프셋 적용
    foreach (Vector3 dir in directions)
    {
        int totalCount = 1 + _upgrade.FrontArrowLevel;
        Vector3 perp = Vector3.Cross(Vector3.up, dir).normalized;  // ①

        for (int i = 0; i < totalCount; i++)
        {
            float offset = (i - (totalCount - 1) / 2f) * 0.4f;  // ②
            Vector3 spawnPos = transform.position + dir * 0.5f + perp * offset;
            spawnPos.y = 1f;

            GameObject go = ObjectPool.Instance.Get(_projectilePrefab);
            go.transform.position = spawnPos;
            go.transform.rotation = Quaternion.LookRotation(dir);
            ProjectileBase proj = go.GetComponent<ProjectileBase>();
            if (proj != null)
                proj.Init(data);
        }
    }
}

private List<Vector3> BuildDirections(Vector3 baseDir)
{
    List<Vector3> dirs = new List<Vector3> { baseDir };

    if (_upgrade.HasDiagonalArrow)  // 사선 화살: ±45°
    {
        dirs.Add(Quaternion.Euler(0, 45, 0) * baseDir);
        dirs.Add(Quaternion.Euler(0, -45, 0) * baseDir);
    }
    if (_upgrade.HasSideArrow)  // 측면 화살: ±90°
    {
        dirs.Add(Quaternion.Euler(0, 90, 0) * baseDir);
        dirs.Add(Quaternion.Euler(0, -90, 0) * baseDir);
    }
    if (_upgrade.HasBackArrow)  // 후방 화살: 180°
    {
        dirs.Add(Quaternion.Euler(0, 180, 0) * baseDir);
    }
    return dirs;
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | 발사 방향(`dir`)과 월드 위쪽(`Vector3.up`)의 외적으로, 발사 방향에 수직인 수평 벡터를 구한다. 이 벡터를 기준으로 FrontArrow를 좌우로 평행 배치한다 |
| ② | `totalCount`개의 화살을 중심(0) 기준으로 균등하게 배치한다. 예: 3개이면 오프셋이 -0.4, 0, +0.4가 되어 0.4m 간격으로 평행하게 날아간다 |
| ③ | 잃은 HP 비율(`missingHpPercent`)에 비례하여 공격력을 곱연산으로 증가시킨다. HP가 낮을수록 강해지는 하이리스크 하이리턴 구조 |
| ④ | 업그레이드 크리티컬 확률과 장비 크리티컬 확률을 합산하여, 두 시스템의 보너스가 누적 적용된다 |

## 데미지 / 생존 시스템

> **왜 피해 저항을 곱연산으로 처리하는가?** `damage *= (1 - resistance/100)`은 저항을 비율 감소로 적용한다. 덧셈 방식(`damage -= resistance`)은 저항이 높으면 음수 데미지가 되어 회복 버그가 생길 수 있다. 곱연산은 `Mathf.Clamp01`로 0~100% 범위를 강제하므로, **아무리 저항을 쌓아도 데미지가 0 이하로 내려가거나 100%를 넘기는 일이 없다.**

```csharp
public void TakeDamage(float damage)
{
    if (_state == EState.Die) return;

    // 장비 피해 저항
    float resistance = EquipmentManager.Instance
        .GetTotalSubStat(ESubStatType.DamageResistance);
    damage *= (1f - Mathf.Clamp01(resistance / 100f));  // ①

    _currentHp -= damage;
    DamageTextSpawner.Spawn(transform.position + Vector3.up * 1.5f, damage, true);

    if (_hpBar != null)
        _hpBar.SetHP(_currentHp, _maxHp);

    if (_currentHp <= 0f)
    {
        // Extra Life 부활
        if (_upgrade.HasExtraLife)
        {
            _upgrade.ConsumeExtraLife();  // ②
            _currentHp = _maxHp;
            if (_hpBar != null)
                _hpBar.SetHP(_currentHp, _maxHp);
            StartCoroutine(ReviveSequence());  // 슬로우모션 3초
            return;
        }

        _currentHp = 0f;
        State = EState.Die;
    }
}

// HP 부스트: 최대 HP 비례 증가 + 즉시 회복
public void BoostHp(float maxHpPercent, float healPercent)
{
    float addMax = _maxHp * maxHpPercent;
    _maxHp += addMax;
    _currentHp = Mathf.Min(_currentHp + addMax * healPercent, _maxHp);  // ④
    if (_hpBar != null)
        _hpBar.SetHP(_currentHp, _maxHp);
}

// 장비 변경 시 최대 HP 재계산 (비례 유지)
public void RecalculateMaxHp()
{
    float ratio = _maxHp > 0 ? _currentHp / _maxHp : 1f;  // ③
    float baseMax = _maxHp - EquipmentManager.Instance.GetTotalMaxHpBonus();
    _maxHp = baseMax + EquipmentManager.Instance.GetTotalMaxHpBonus();
    _currentHp = _maxHp * ratio;
    if (_hpBar != null)
        _hpBar.SetHP(_currentHp, _maxHp);
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | 저항값을 0~1 범위로 클램핑 후 `(1 - 저항률)`을 곱한다. 저항 50이면 데미지 50% 감소, 100이면 0으로 만든다. 음수 데미지(회복 버그)가 발생하지 않는다 |
| ② | Extra Life를 1회 소비하고 HP를 최대치로 즉시 복원한다. 소비형이므로 두 번째 사망 시에는 부활하지 않는다 |
| ③ | 장비 변경 전 현재 HP와 최대 HP의 비율을 기록한다. 장비로 최대 HP가 변해도 이 비율을 유지하여 HP가 갑자기 가득 차거나 줄어드는 것을 방지한다 |
| ④ | 추가된 최대 HP의 `healPercent`만큼만 즉시 회복하되, 최대 HP를 초과하지 않도록 `Min`으로 제한한다 |

### 데미지 계산 흐름

```
몬스터 접촉 / 투사체 피격
         │
         ▼
TakeDamage(rawDamage)
    │  resistance = 장비 피해저항 합산
    │  damage *= (1 - resistance/100)
    ▼
_currentHp -= damage
    │
    ├── hp > 0 → DamageText 표시 + HPBar 갱신
    │
    └── hp <= 0
         ├── HasExtraLife? → ConsumeExtraLife + HP 풀 회복 + 슬로우모션 3초
         └── → State = Die
```

## Push / Knockback 메커니즘

> **왜 `CharacterController.Move()`로 밀기를 구현하는가?** `transform.position`을 직접 변경하면 벽을 뚫고 지나가는 버그가 생긴다. `CharacterController.Move()`는 내장 충돌 판정이 있어 **벽에 닿으면 자동으로 슬라이딩**되므로, 밀려도 벽을 뚫지 않는다.

```csharp
public void Push(Vector3 displacement)
{
    if (_state == EState.Die) return;
    _controller.Move(displacement);  // ① CC의 충돌 판정 활용
}

// 플레이어가 몬스터를 밀 때
private void OnControllerColliderHit(ControllerColliderHit hit)
{
    MonsterBase monster = hit.gameObject.GetComponentInParent<MonsterBase>();
    if (monster == null || monster.CurrentHp <= 0) return;
    if (_weight <= monster.Weight) return;                     // ② 무게 비교
    Rigidbody rb = hit.rigidbody;
    if (rb == null || rb.isKinematic) return;
    Vector3 pushDir = hit.moveDirection;
    pushDir.y = 0;
    rb.AddForce(pushDir.normalized * (_weight - monster.Weight),
        ForceMode.Impulse);                                    // ③
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | 몬스터가 플레이어를 밀 때 `_controller.Move(displacement)`로 이동한다. CharacterController의 충돌 판정이 자동으로 벽 뚫기를 방지한다 |
| ② | 플레이어 무게(`_weight=5`)가 몬스터 무게 이하이면 밀기를 수행하지 않는다. 보스급 몬스터는 플레이어가 밀 수 없다 |
| ③ | 무게 차이에 비례한 `Impulse` 힘으로 몬스터의 Rigidbody를 밀어낸다. 무게 차이가 클수록 세게 밀린다 |

### 밀기 상호작용

```
몬스터 → 플레이어 밀기 (OnCollisionStay)
    조건: monster.Weight > player.Weight
    방법: player.Push(pushDir × (weight차) × 0.5 × dt)
    안전: CharacterController.Move() → 벽 뚫기 방지

플레이어 → 몬스터 밀기 (OnControllerColliderHit)
    조건: player.Weight > monster.Weight
    방법: rb.AddForce(pushDir × weight차, Impulse)
    안전: Rigidbody 물리 → 자연스러운 밀림
```

## ApplyUpgradeEffect() - 업그레이드 즉시 효과

> **왜 별도 메서드로 분리했는가?** `PlayerUpgrade.AddUpgrade()`는 레벨과 수치를 증가시키는 **데이터 변경**이고, `ApplyUpgradeEffect()`는 콜라이더 전환, 스케일 변경 등 **월드에 즉시 반영되는 효과**다. 데이터와 시각/물리 효과를 분리하면, 업그레이드 데이터를 로드할 때는 AddUpgrade만 호출하고, 게임 중 선택 시에만 ApplyUpgradeEffect를 추가 호출하는 식으로 **상황에 따라 선택적으로 적용**할 수 있다.

```csharp
public void ApplyUpgradeEffect(EUpgradeType type)
{
    switch (type)
    {
        case EUpgradeType.WallPass:
            if (_passability != null)
                _passability.AddFlag(ETilePassFlag.WallPass);
            ApplyWallPassCollisions();                         // ①
            break;
        case EUpgradeType.WaterWalker:
            if (_passability != null)
                _passability.AddFlag(ETilePassFlag.WaterWalk);
            ApplyWaterWalkCollisions();                        // ②
            break;
        case EUpgradeType.Dwarf:
            var dwarfInfo = UpgradeDatabase.GetInfo(EUpgradeType.Dwarf);
            transform.localScale *= dwarfInfo?.scale ?? 0.9f;  // ③
            break;
        case EUpgradeType.Giant:
            var giantInfo = UpgradeDatabase.GetInfo(EUpgradeType.Giant);
            transform.localScale *= giantInfo?.scale ?? 1.1f;  // ④
            break;
        case EUpgradeType.HpBoost:
            BoostHp(_upgrade.HpBoostPercent, _upgrade.HpBoostHealPercent);
            break;
        case EUpgradeType.FastGrowth:
            ExpManager.Instance.SetMaxLevel(_upgrade.MaxPlayerLevel);  // ⑤
            break;
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | WallPass: 타일 통과 플래그 추가 + 현재 씬의 모든 비경계 BlockObstacle 콜라이더를 트리거로 전환한다 |
| ② | WaterWalker: 수상 보행 플래그 추가 + WaterObstacle 콜라이더를 트리거로 전환한다 |
| ③ | Dwarf: 캐릭터를 축소(0.9배)하여 피탄 면적을 줄인다. 크리티컬 확률 보너스는 PlayerUpgrade에서 자동 적용된다 |
| ④ | Giant: 캐릭터를 확대(1.1배)하여 시각적 존재감을 강화한다. 공격력 보너스는 PlayerUpgrade에서 자동 적용된다 |
| ⑤ | FastGrowth: 최대 레벨을 상향하여 더 많은 레벨업(= 더 많은 업그레이드 선택)이 가능하게 한다 |

### ApplyWallPassCollisions / ApplyWaterWalkCollisions

> **왜 콜라이더를 트리거로 전환하는가?** Unity의 `CharacterController.Move()`는 `isTrigger=false`인 콜라이더에 충돌하여 통과하지 못한다. `isTrigger=true`로 전환하면 CC가 해당 콜라이더를 **무시하고 통과**하게 된다. 경계 벽(`IsBoundary`)은 항상 막아야 하므로 제외한다.

```csharp
public void ApplyWallPassCollisions()
{
    BlockObstacle[] blocks = FindObjectsByType<BlockObstacle>(FindObjectsSortMode.None);
    foreach (BlockObstacle block in blocks)
    {
        if (block.IsBoundary) continue;           // ① 경계 벽은 항상 막음
        Collider col = block.GetComponent<Collider>();
        if (col != null) col.isTrigger = true;    // ② 트리거 전환 → CC 통과 허용
    }
}

public void ApplyWaterWalkCollisions()
{
    WaterObstacle[] waters = FindObjectsByType<WaterObstacle>(FindObjectsSortMode.None);
    foreach (WaterObstacle water in waters)
    {
        Collider col = water.GetComponent<Collider>();
        if (col != null) col.isTrigger = true;
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | `IsBoundary`인 블록은 스킵하여 맵 경계를 항상 유지한다. WallPass가 있어도 맵 밖으로 나갈 수 없다 |
| ② | 콜라이더를 트리거로 전환하면 CharacterController가 해당 오브젝트를 통과할 수 있게 된다 |

## 상태 머신

> **왜 `State` setter에서 애니메이션을 자동 동기화하는가?** 상태 변경과 애니메이션 전환을 별도로 호출하면, 한쪽만 호출하는 실수로 "Idle 상태인데 Attack 애니메이션이 재생"되는 불일치 버그가 생긴다. `State` 프로퍼티의 setter에서 자동으로 `UpdateAnimation()`을 호출하면, **상태를 바꾸는 것만으로 애니메이션이 항상 동기화**되어 이런 류의 버그를 구조적으로 방지할 수 있다.

```csharp
private void UpdateAnimation()
{
    switch (State)
    {
        case EState.Idle:
            _animator.speed = 1f;
            _animator.CrossFade(IsServing ? Define.SERVING_IDLE : Define.IDLE, 0.1f);
            break;
        case EState.Move:
            _animator.speed = 1f;
            _animator.CrossFade(IsServing ? Define.SERVING_MOVE : Define.MOVE, 0.05f);
            break;
        case EState.Attack:
            _animator.CrossFade(Define.ATTACK, 0.1f, 0, 0f);
            break;
        case EState.Die:
            _animator.CrossFade(Define.DIE, 0.1f);
            break;
    }
}
```

### 상태 전이 다이어그램

```
     ┌────── Move ◄──────┐
     │   (조이스틱 입력)   │
     ▼                    │
   Idle ──────────────► Attack
 (타겟 없음)         (정지 + 타겟)
     │                    │
     ▼                    ▼
    Die ◄──────────── Die
 (HP <= 0, Extra Life 없음)
```
