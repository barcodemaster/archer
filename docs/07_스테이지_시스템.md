# 07. 스테이지 시스템

## 개요

`StageManager`가 스테이지 라이프사이클(로드→전투→클리어→전환)을 관리하고, 드롭 아이템과 ExitDoor를 제어합니다.

## StartStage() - 스테이지 초기화

> `Assets/Scripts/Manager/StageManager.cs`

> **왜 5종류의 잔여 오브젝트를 각각 Destroy하는가?** 스테이지 전환 시 이전 스테이지의 드롭 아이템이 남아있으면, 새 스테이지에서 이전 오브의 수집 이벤트가 발동하여 이중 보상 버그가 생긴다. 각 리스트를 순회하며 null 체크 후 Destroy하는 패턴으로 **모든 잔여 오브젝트를 안전하게 정리**한다.

```csharp
public void StartStage(int index)
{
    _currentStageIndex = index;

    if (index >= _stageTileMapPrefabs.Count)                 // ①
    {
        Debug.Log("All stages cleared!");
        return;
    }

    // ── 이전 스테이지 정리 ──
    if (_currentTileMapInstance != null)
        Destroy(_currentTileMapInstance);                     // ②

    foreach (var m in _aliveMonsters)
        if (m != null) Destroy(m.gameObject);
    _aliveMonsters.Clear();

    foreach (var orb in _spawnedExpOrbs)
        if (orb != null) Destroy(orb.gameObject);
    _spawnedExpOrbs.Clear();

    foreach (var heart in _spawnedHpHearts)
        if (heart != null) Destroy(heart.gameObject);
    _spawnedHpHearts.Clear();

    foreach (var orb in _spawnedGoldOrbs)
        if (orb != null) Destroy(orb.gameObject);
    _spawnedGoldOrbs.Clear();

    foreach (var orb in _spawnedEquipmentOrbs)
        if (orb != null) Destroy(orb.gameObject);
    _spawnedEquipmentOrbs.Clear();

    // ── 새 TileMap 생성 ──
    _currentTileMapInstance = Instantiate(_stageTileMapPrefabs[index]);
    _tileMap = _currentTileMapInstance.GetComponent<TileMap>();
    _tileMap.GenerateVisuals();                               // ③
    _exitDoor = _tileMap.SpawnedExitDoor;

    // ── 플레이어 텔레포트 ──
    TeleportPlayerToSpawn();                                  // ④

    // ── 몬스터 스폰 ──
    if (_tileMap.MonsterPrefabs != null)
    {
        foreach (var entry in _tileMap.PlacedMonsters)
        {
            if (entry.prefabIndex < 0 ||
                entry.prefabIndex >= _tileMap.MonsterPrefabs.Length) continue;  // ⑤
            GameObject go = Instantiate(
                _tileMap.MonsterPrefabs[entry.prefabIndex],
                _tileMap.GridToWorld(entry.pos.x, entry.pos.y),
                Quaternion.LookRotation(Vector3.back));
            MonsterBase mb = go.GetComponent<MonsterBase>();
            if (mb != null) _aliveMonsters.Add(mb);
        }
    }

    // ── 업그레이드 재적용 ──
    PlayerController player = FindAnyObjectByType<PlayerController>();
    if (player != null)
    {
        PlayerUpgrade upgrade = player.GetComponent<PlayerUpgrade>();
        if (upgrade != null)
        {
            if (upgrade.GetLevel(Define.EUpgradeType.WallPass) > 0)
                player.ApplyWallPassCollisions();              // ⑥
            if (upgrade.GetLevel(Define.EUpgradeType.WaterWalker) > 0)
                player.ApplyWaterWalkCollisions();
        }
    }

    if (_aliveMonsters.Count == 0)
        OpenExitDoor();                                        // ⑦
}
```

### 코드 해설
| # | 설명 |
|---|------|
| ① | 스테이지 인덱스가 전체 개수를 넘으면 모든 스테이지 클리어로 판정하고 조기 리턴한다 |
| ② | 이전 TileMap 인스턴스를 Destroy하여 씬에 타일맵이 중복 존재하는 것을 방지한다 |
| ③ | `GenerateVisuals()`로 타일 바닥, 벽 블록, 경계벽, 콜라이더를 런타임에 생성한다. Static Batching도 이 시점에 적용된다 |
| ④ | `TeleportPlayerToSpawn()`으로 CharacterController를 disable→위치 설정→enable하여 안전하게 텔레포트한다 |
| ⑤ | prefabIndex가 유효 범위 밖이면 건너뛴다. 에디터에서 몬스터 프리팹을 삭제해도 런타임 크래시 없이 해당 슬롯만 스킵한다 |
| ⑥ | 새 TileMap에도 WallPass/WaterWalker 업그레이드 효과를 재적용한다. 스테이지 전환 시 BlockObstacle/WaterObstacle이 새로 생성되므로 콜라이더를 다시 트리거로 전환해야 한다 |
| ⑦ | 몬스터가 0마리인 빈 스테이지면 즉시 출구를 연다. 테스트/보너스 스테이지 용도 |

> **왜 WallPass/WaterWalker를 재적용하는가?** `ApplyWallPassCollisions()`는 현재 씬의 모든 `BlockObstacle`을 찾아 콜라이더를 트리거로 전환한다. 스테이지 전환 시 이전 블록은 Destroy되고 새 블록이 생성되므로, **이전 스테이지에서 적용한 효과가 사라진다.** 따라서 매 스테이지 시작 시 업그레이드를 보유하고 있으면 다시 적용해야 한다.

## TeleportPlayerToSpawn() - 안전한 텔레포트

> **왜 CharacterController를 비활성화하고 텔레포트하는가?** Unity의 `CharacterController`는 자체 위치 보정 로직이 있어, `transform.position`을 직접 변경해도 다음 프레임에 원래 위치로 돌아가는 문제가 있다. 비활성화(disable) → 위치 설정 → 재활성화(enable) 순서로 처리하면 **CC의 위치 보정을 우회하여 안전하게 텔레포트**할 수 있다.

```csharp
private void TeleportPlayerToSpawn()
{
    if (_tileMap == null) return;
    PlayerController player = FindAnyObjectByType<PlayerController>();
    if (player == null) return;
    Vector3 spawnPos = _tileMap.GetSpawnWorldPosition();
    CharacterController cc = player.GetComponent<CharacterController>();
    if (cc != null) cc.enabled = false;   // ① CC 비활성화
    player.transform.position = spawnPos; // ② 위치 직접 설정
    if (cc != null) cc.enabled = true;    // ③ CC 재활성화
}
```

### 코드 해설
| # | 설명 |
|---|------|
| ① | CharacterController를 비활성화하여 내부 위치 보정 로직을 중단한다 |
| ② | CC가 비활성화된 상태에서 transform.position을 직접 변경한다 |
| ③ | CC를 다시 활성화하면 새 위치를 기준으로 물리 상태가 초기화된다 |

## OnMonsterDead() - 몬스터 사망 처리

> **왜 GetRandomDropOffset()으로 위치를 분산하는가?** 4종의 드롭 아이템(Exp, HP, Gold, Equipment)이 모두 같은 위치에 생성되면 오브가 겹쳐서 하나만 보이는 시각적 문제가 생긴다. 반경 0.5f 내 랜덤 오프셋으로 **각 드롭 아이템이 약간씩 흩어져 스폰**되어, 플레이어가 여러 종류의 보상을 시각적으로 구분할 수 있다.

```csharp
public void OnMonsterDead(MonsterBase monster)
{
    _aliveMonsters.Remove(monster);                           // ①
    Vector3 basePos = monster.transform.position;
    SpawnExpOrb(basePos + GetRandomDropOffset(), monster.ExpReward);

    // 피의갈증: 처치 시 HP 회복
    PlayerController player = FindAnyObjectByType<PlayerController>();
    if (player != null)
    {
        PlayerUpgrade upgrade = player.GetComponent<PlayerUpgrade>();
        if (upgrade != null && upgrade.BloodThirstHealPercent > 0f)
            player.Heal(player.MaxHp * upgrade.BloodThirstHealPercent);  // ②
    }

    SpawnHpHeart(basePos + GetRandomDropOffset());            // ③
    SpawnGoldOrb(basePos + GetRandomDropOffset());            // ④
    SpawnEquipmentOrb(basePos + GetRandomDropOffset());       // ⑤

    if (_aliveMonsters.Count == 0)                            // ⑥
    {
        CollectAllExpOrbs();
        CollectAllHpHearts();
        CollectAllGoldOrbs();
        CollectAllEquipmentOrbs();
        OpenExitDoor();
    }
}
```

### 코드 해설
| # | 설명 |
|---|------|
| ① | 사망한 몬스터를 alive 목록에서 제거한다. 이 시점에서 몬스터 게임오브젝트는 아직 존재하므로 position 참조가 가능하다 |
| ② | BloodThirst 업그레이드가 있으면 최대 HP의 일정 비율만큼 즉시 회복한다. 많은 몬스터를 처치할수록 생존력이 높아지는 어그레시브 플레이 보상이다 |
| ③ | 15% 확률로 HP 하트를 드롭한다. 확률 판정은 `SpawnHpHeart()` 내부에서 수행한다 |
| ④ | 모든 몬스터 사망 시 골드 오브를 드롭한다. 5~15 범위의 랜덤 골드를 포함한다 |
| ⑤ | 5% 확률로 장비 오브를 드롭한다. `EquipmentManager.CreateRandomItem()`으로 랜덤 장비를 생성한다 |
| ⑥ | 마지막 몬스터가 죽으면 4종의 CollectAll을 호출하여 모든 대기 중 오브에 수집을 시작시키고, 출구를 연다 |

## RegisterMonster() - 동적 몬스터 등록

> **왜 별도 등록 메서드가 필요한가?** `SplitterMonster`가 사망 시 자식 몬스터를 동적 생성한다. `StartStage()`에서 등록된 몬스터만 `_aliveMonsters`에서 추적하므로, 동적 생성 몬스터를 등록하지 않으면 **자식이 살아있는데 스테이지 클리어가 발동**되는 버그가 생긴다.

```csharp
public void RegisterMonster(MonsterBase monster)
{
    if (!_aliveMonsters.Contains(monster))  // ① 중복 등록 방지
        _aliveMonsters.Add(monster);
}
```

### 코드 해설
| # | 설명 |
|---|------|
| ① | `Contains` 체크로 같은 몬스터가 두 번 등록되는 것을 방지한다. 중복 등록되면 사망 시 `Remove`가 하나만 제거하여 카운트 불일치가 생긴다 |

### SplitterMonster 연동 흐름

```
SplitterMonster 사망
    │
    ▼ OnDie() 오버라이드
자식 몬스터 2마리 Instantiate
    │
    ▼ 각 자식에 대해
StageManager.Instance.RegisterMonster(child)
    │  → _aliveMonsters에 추가
    ▼
전멸 판정 시 자식 포함하여 카운트
```

## StageTransitionSequence() - 페이드 전환

```csharp
public void GoToNextStage()
{
    StartCoroutine(StageTransitionSequence(_currentStageIndex + 1));
}

private IEnumerator StageTransitionSequence(int nextIndex)
{
    yield return UIManager.Instance.FadeOut(_fadeDuration);   // ① 화면 어두워짐
    UIManager.Instance.HideStageProgress();                   // ② 진행도 UI 숨김
    StartStage(nextIndex);                                    // ③ 새 스테이지 로드
    yield return UIManager.Instance.FadeIn(_fadeDuration);    // ④ 화면 밝아짐
}
```

### 코드 해설
| # | 설명 |
|---|------|
| ① | FadeOut으로 화면을 검은색으로 덮어 스테이지 전환 과정(Destroy/Instantiate)이 보이지 않게 한다 |
| ② | 이전 스테이지의 진행도 슬라이더를 숨긴다 |
| ③ | FadeOut이 완료된 후 StartStage로 새 스테이지를 로드한다. 이전 오브젝트 정리 + 새 TileMap 생성이 검은 화면 뒤에서 수행된다 |
| ④ | 새 스테이지가 준비된 후 FadeIn으로 화면을 밝혀 플레이어에게 새 스테이지를 보여준다 |

## OpenExitDoorSequence() - 출구 열기

```csharp
private IEnumerator OpenExitDoorSequence()
{
    GoldManager.Instance.AddGold(_stageGoldReward);          // ① 클리어 보상 골드
    yield return new WaitForSeconds(1.5f);                    // ② 대기

    if (_exitDoor == null) yield break;
    ExitDoor door = _exitDoor.GetComponent<ExitDoor>();
    if (door != null)
        door.OpenDoor();                                      // ③ 문 열기 연출

    OnExitDoorOpened?.Invoke();                               // ④ 이벤트 발행
}
```

### 코드 해설
| # | 설명 |
|---|------|
| ① | 스테이지 클리어 보상으로 고정 100골드를 즉시 지급한다. 몬스터 드롭 골드와 별도의 클리어 보너스다 |
| ② | 1.5초 대기로 드롭 오브가 플레이어에게 날아와 수집되는 시간을 확보한다 |
| ③ | ExitDoor의 열림 연출(Blocker 제거, 렌더러 교체, Point Light, 파티클, 트리거 활성화)을 시작한다 |
| ④ | `OnExitDoorOpened` 이벤트로 UI_StageProgress 등 외부 시스템에 클리어를 알린다 |

> **왜 1.5초 딜레이가 있는가?** 스테이지 클리어 직후 바로 출구가 열리면, 드롭 아이템이 플레이어에게 날아오는 도중에 다음 스테이지로 넘어갈 수 있다. 1.5초 딜레이는 **모든 드롭 오브가 수집되고, 골드 보상이 표시되는 시간을 확보**하여 플레이어가 보상을 확인하는 여유를 준다.

## 드롭 시스템

### SpawnGoldOrb() - 골드 오브 생성

> **왜 프리팹 null일 때 fallback 직접 적용인가?** 프리팹이 Inspector에 할당되지 않은 상태에서도 골드 시스템이 동작해야 한다. 프리팹이 없으면 시각적 오브 없이 `GoldManager.AddGold()`를 직접 호출하여 **하위 호환성을 보장**한다. 개발 초기 프리팹 미완성 단계에서도 골드 로직을 테스트할 수 있다.

```csharp
private void SpawnGoldOrb(Vector3 pos)
{
    if (_goldOrbPrefab == null)                                // ① fallback
    {
        GoldManager.Instance.AddGold(
            UnityEngine.Random.Range(_monsterGoldMin, _monsterGoldMax + 1));
        return;
    }

    int gold = UnityEngine.Random.Range(_monsterGoldMin, _monsterGoldMax + 1);  // ②
    GameObject go = Instantiate(_goldOrbPrefab, pos, Quaternion.identity);
    GoldOrb orb = go.GetComponent<GoldOrb>();
    if (orb != null)
    {
        orb.Init(gold);                                        // ③
        _spawnedGoldOrbs.Add(orb);
    }
}
```

### 코드 해설
| # | 설명 |
|---|------|
| ① | 프리팹 미할당 시 시각적 오브 없이 골드를 직접 지급한다. 개발 중 프리팹 없이도 골드 로직이 동작하는 하위 호환 패턴이다 |

### ExpOrb - 경험치 오브

> `Assets/Scripts/Stage/ExpOrb.cs`

> **왜 Init → 대기 → 수집 3단계인가?** 몬스터가 죽자마자 경험치가 바로 적용되면, 플레이어는 수치가 올라간 것만 볼 뿐 "획득했다"는 느낌을 받지 못한다. 오브가 바닥에서 bobbing으로 대기하다가, 스테이지 클리어 시 일괄적으로 플레이어에게 날아오면 **"전리품을 쓸어담는" 시각적 쾌감**이 생긴다. 이 3단계 패턴은 모든 드롭 아이템(Gold, HP, Equipment)에 동일하게 적용된다.

```csharp
public class ExpOrb : MonoBehaviour
{
    [SerializeField] private float _flySpeed = 8f;
    [SerializeField] private float _arriveDistance = 0.3f;
    [SerializeField] private float _bobAmplitude = 0.2f;
    [SerializeField] private float _bobFrequency = 2f;

    private int _expAmount;
    private bool _waiting;     // 대기 상태 (바닥에서 bobbing)
    private bool _collecting;  // 수집 상태 (플레이어로 비행)

    public void Init(int expAmount)
    {
        _expAmount = expAmount;
        _spawnPos = transform.position;
        _waiting = true;
    }

    public void StartCollect()
    {
        _waiting = false;
        _collecting = true;
        _target = FindAnyObjectByType<PlayerController>()?.transform;
    }

    private void Update()
    {
        if (_waiting)
        {
            // bobbing 애니메이션 (사인파)
            float yOffset = Mathf.Sin(Time.time * _bobFrequency) * _bobAmplitude;  // ①
            transform.position = _spawnPos + Vector3.up * yOffset;
            return;
        }

        if (!_collecting) return;

        // 가속 비행: 시간 + 거리 비례 속도 증가
        _elapsed += Time.deltaTime;
        float speed = Mathf.Max(
            _flySpeed + _elapsed * 10f,  // ②
            _flySpeed + dir.magnitude * 2f);  // ③
        transform.position = Vector3.MoveTowards(  // ④
            transform.position, _target.position, speed * Time.deltaTime);

        // 도착 → 경험치 전달
        if (dir.magnitude <= _arriveDistance)
        {
            AudioManager.Instance?.PlayExpCollect();
            ExpManager.Instance.AddExp(_expAmount);
            Destroy(gameObject);
        }
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | `Sin(Time.time × 주파수) × 진폭`으로 사인파 bobbing을 만든다. 시간에 따라 Y 위치가 위아래로 부드럽게 흔들리는 대기 애니메이션이다 |
| ② | 경과 시간에 비례하여 속도가 증가한다(`+_elapsed×10`). 처음엔 느리게, 점점 빨라지며 플레이어에게 빨려 들어가는 연출이다 |
| ③ | 남은 거리에도 비례하여 속도를 올린다. 멀리 있는 오브가 너무 느리게 날아오는 것을 방지하는 보조 가속이다 |
| ④ | `MoveTowards`는 현재 위치에서 목표까지 최대 `speed×dt`만큼만 이동하여, 목표를 지나치지 않는 안전한 이동을 보장한다 |

### GoldOrb - 골드 오브

> `Assets/Scripts/Stage/GoldOrb.cs`

```csharp
public class GoldOrb : MonoBehaviour
{
    [SerializeField] private float _flySpeed = 8f;
    [SerializeField] private float _arriveDistance = 0.3f;
    [SerializeField] private float _bobAmplitude = 0.2f;
    [SerializeField] private float _bobFrequency = 2f;

    private int _goldAmount;
    private bool _waiting;
    private bool _collecting;

    public void Init(int goldAmount)                          // ①
    {
        _goldAmount = goldAmount;
        _spawnPos = transform.position;
        _waiting = true;
        _collecting = false;
    }

    public void StartCollect()                                // ②
    {
        _waiting = false;
        _collecting = true;
        PlayerController player = FindAnyObjectByType<PlayerController>();
        if (player != null) _target = player.transform;
        _elapsed = 0f;
    }

    private void Update()
    {
        if (_waiting)
        {
            float yOffset = Mathf.Sin(Time.time * _bobFrequency) * _bobAmplitude;
            transform.position = _spawnPos + Vector3.up * yOffset;
            return;
        }

        if (!_collecting) return;

        if (_target == null)                                   // ③
        {
            GoldManager.Instance.AddGold(_goldAmount);
            Destroy(gameObject);
            return;
        }

        Vector3 dir = (_target.position - transform.position);
        if (dir.magnitude <= _arriveDistance)                   // ④
        {
            GoldManager.Instance.AddGold(_goldAmount);
            Destroy(gameObject);
            return;
        }

        _elapsed += Time.deltaTime;
        float speed = Mathf.Max(_flySpeed + _elapsed * 10f, _flySpeed + dir.magnitude * 2f);
        transform.position = Vector3.MoveTowards(
            transform.position, _target.position, speed * Time.deltaTime);
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | `Init(goldAmount)`로 골드량을 저장하고 대기 상태로 진입한다. ExpOrb와 동일한 3단계 패턴이다 |
| ② | `StartCollect()` 호출 시 플레이어 Transform을 찾아 추적 대상으로 설정하고 비행을 시작한다 |
| ③ | 플레이어가 null(사망 등)이면 골드를 직접 지급하고 자신을 파괴한다. 안전한 fallback 처리다 |
| ④ | 도착 거리 이내에 도달하면 `GoldManager.AddGold()`로 골드를 지급하고 오브를 파괴한다 |

| 아이템 | 드롭 조건 | Init 인자 | 대기 | 수집 | 도착 효과 |
|--------|----------|-----------|------|------|----------|
| **ExpOrb** | 모든 몬스터 사망 | `int exp` | bobbing | 가속 비행 | `ExpManager.AddExp` |
| **GoldOrb** | 모든 몬스터 사망 | `int gold` | bobbing | 가속 비행 | `GoldManager.AddGold` |
| **HPHeart** | 15% 확률 | (없음) | bobbing | 가속 비행 | `PlayerController.Heal` |
| **EquipmentOrb** | 5% 확률 | `EquipmentData` | bobbing | 가속 비행 | `EquipmentManager.AddItem` |

모든 드롭 아이템은 동일한 3단계 패턴을 따릅니다:
1. `Init()` → 대기 상태 (bobbing 애니메이션)
2. 스테이지 클리어 시 `StartCollect()` → 플레이어로 가속 비행
3. 도착 → 효과 적용 + Destroy

## ExitDoor - 출구 문

> `Assets/Scripts/Stage/ExitDoor.cs`

```csharp
public class ExitDoor : MonoBehaviour
{
    [SerializeField] private GameObject _openDoorPrefab;
    [SerializeField] private float _openDelay = 1.5f;
    [SerializeField] private float _lightIntensity = 50f;
    [SerializeField] private Color _lightColor = Color.yellow;

    private GameObject _blocker;
    private Collider _collider;
    private bool _triggered;

    private void Start()
    {
        // 콜라이더 비활성화 (클리어 전까지 진입 불가)
        _collider = GetComponent<Collider>();
        if (_collider != null) _collider.enabled = false;  // ①

        // Blocker 오브젝트 참조 (계단 차단)
        Transform blockerTransform = transform.Find("Blocker");
        if (blockerTransform != null)
            _blocker = blockerTransform.gameObject;
    }

    public void OpenDoor()
    {
        StartCoroutine(OpenDoorSequence());
    }

    private IEnumerator OpenDoorSequence()
    {
        yield return new WaitForSeconds(_openDelay);

        // 1. 계단 차단 해제
        if (_blocker != null) _blocker.SetActive(false);  // ②

        // 2. 기존 렌더러 숨김
        Renderer[] renderers = GetComponentsInChildren<Renderer>();
        foreach (var r in renderers) r.enabled = false;

        // 3. 열린 문 프리팹 생성 (콜라이더 제거)
        if (_openDoorPrefab != null)
        {
            GameObject openDoor = Instantiate(_openDoorPrefab, transform.position,
                transform.rotation, transform);
            foreach (var c in openDoor.GetComponentsInChildren<Collider>())
                Destroy(c);
        }

        // 4. Point Light 생성 (노란 빛)
        GameObject lightObj = new GameObject("DoorLight");
        lightObj.transform.SetParent(transform);
        lightObj.transform.localPosition = Vector3.up * 1.5f;
        Light pointLight = lightObj.AddComponent<Light>();
        pointLight.type = LightType.Point;
        pointLight.color = _lightColor;
        pointLight.intensity = _lightIntensity;
        pointLight.range = 8f;

        // 5. Particle 이펙트 (URP 호환 머티리얼)
        // ... Cone 형태 파티클 시스템 생성

        // 6. 트리거 콜라이더 활성화
        if (_collider != null) _collider.enabled = true;  // ③
    }

    private void OnTriggerEnter(Collider other)
    {
        if (_triggered) return;  // ④
        if (other.GetComponent<PlayerController>() != null)
        {
            _triggered = true;
            StageManager.Instance.GoToNextStage();
        }
    }
}
```

#### 코드 해설
| # | 설명 |
|---|------|
| ① | 스테이지 시작 시 트리거 콜라이더를 비활성화하여, 몬스터를 모두 처치하기 전에는 출구에 진입할 수 없게 한다 |
| ② | 계단을 막고 있던 Blocker 오브젝트를 비활성화하여 물리적 차단을 해제한다 |
| ③ | 문 열림 연출이 끝난 후 트리거 콜라이더를 활성화하여, 비로소 플레이어가 출구에 진입할 수 있게 된다 |
| ④ | `_triggered` 플래그로 중복 진입을 방지한다. OnTriggerEnter가 여러 프레임에 걸쳐 호출되어도 `GoToNextStage()`는 한 번만 실행된다 |

### ExitDoor 타임라인

```
스테이지 클리어
    │
    ▼ 1.5초 대기 (OpenExitDoorSequence)
골드 보상 지급 (_stageGoldReward)
    │
    ▼ 1.5초 대기 (OpenDoorSequence)
Blocker 비활성화
    + 렌더러 교체 (닫힌 문 → 열린 문)
```
